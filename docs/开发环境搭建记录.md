## 三、历史网络现象与疑似原因

以下仅描述当时观测，不将单次现象归因为已证实的公司网络策略，也不保证其他时间、地址或软件包可用。

| 实际现象 | 疑似原因与证据边界 | 当时应对方式 |
| --- | --- | --- |
| `Invoke-WebRequest` 出现安全提醒并阻塞 | 当时使用 PowerShell 5.1，可能与其 HTML 解析或安全提示行为有关 | 加 `-UseBasicParsing`，或改用 `curl.exe`；其他命令仍需分别验证 |
| 直连 GitHub、微软 CDN 速度约 10 KB/s | 可能与链路、拥塞、路由或代理策略有关；没有证据确认国际线路被限速 | 当时通过本机代理 `127.0.0.1:7897` 下载较快；代理使用须符合组织政策 |
| `wsl --list --online` 报 `WSL_E_NAME_NOT_RESOLVED` | 提示名称解析相关故障；`raw.githubusercontent.com` 的解析路径可能相关，不能据此认定公司 DNS 主动封锁 | 手动下载镜像后 `wsl --import` |
| apt 报 `NOSPLIT (does the network require authentication?)`，多个响应文件大小同为约 5909 字节 | 可能收到非预期内容、认证页或代理响应；仅凭 NOSPLIT 和大小一致不能定位来源或确认网关拦截 | 改用可达的 HTTPS 镜像，保留 apt 签名验证；后续结合响应头、重定向目标及内容排查 |

优先使用 HTTPS，并按来源验证下载内容。**HTTP 302 仅表示重定向；NOSPLIT 仅是当次解析失败线索，均不能证明公司网关拦截，也不能推出所有 HTTP 下载内容均不可信。** HTTPS 连接成功或返回 200 同样不等同于制品真实性、完整性或业务可用性已获保障。

## 四、历史搭建步骤与校验边界

以下保留操作示例与原记录结果，并补充安全操作建议；不表示本次执行过这些命令，也不表示新增建议已实测。

### 4.1 下载并校验 WSL 安装包

原流程通过 GitHub 发布 API 选择当时的稳定版本。`latest` 为动态地址，重跑时不保证得到记录中的 3.0.1；复现应先确认具体版本与来源。

```powershell
$release = Invoke-RestMethod 'https://api.github.com/repos/microsoft/WSL/releases/latest'
$asset = $release.assets | Where-Object name -Match '^wsl\..*\.x64\.msi$' | Select-Object -First 1
$dest = 'E:\WSL\Installers\' + $asset.name

& curl.exe -L --fail --retry 5 --proxy http://127.0.0.1:7897 --output $dest $asset.browser_download_url

# 查看 Authenticode 校验状态及签署者；应确认 Valid 和预期 Microsoft 签署者
Get-AuthenticodeSignature $dest | Select-Object Status, @{n='Signer';e={$_.SignerCertificate.Subject}}

# 将本地 SHA256 与该发布资产的 digest 逐项比较（digest 可能带 sha256: 前缀）
(Get-FileHash $dest -Algorithm SHA256).Hash.ToLower()
$asset.digest
```

历史记录：

- 版本：`3.0.1`（原记录发布日期为 2026-09-29，本次未复核）。
- 大小：350.6 MB。
- Authenticode：`Valid`，签署者包含 `CN=Microsoft Corporation, O=Microsoft Corporation`。
- SHA256：`28b1a0d013640a2ac95898ea705fa186e5b4ff767a1c1b49257161bc106599c6`，原记录与 GitHub 发布资产 digest 一致。

校验范围：签名状态反映当时本机信任环境下的签名验证结果；哈希比对只证明文件与所获取的发布摘要一致。上述命令仅展示值，不会自动阻止不匹配文件的安装；须人工确认，不匹配或缺少可信摘要时停止安装。两项均不是软件无漏洞或环境合规的保证。

### 4.3 下载并校验 Ubuntu 根文件系统

当时在线列表出现名称解析错误，因此选择手动获取 Ubuntu 镜像；不将该结果扩大为所有在线安装命令必然不可用。

| 项目 | 来源 |
| --- | --- |
| 镜像文件 | `https://cloud-images.ubuntu.com/wsl/releases/24.04/current/ubuntu-noble-wsl-amd64-24.04lts.rootfs.tar.gz` |
| 校验文件 | 同目录的 `SHA256SUMS` |

```powershell
$base = 'https://cloud-images.ubuntu.com/wsl/releases/24.04/current'
$name = 'ubuntu-noble-wsl-amd64-24.04lts.rootfs.tar.gz'

& curl.exe -sS --proxy http://127.0.0.1:7897 -o 'E:\WSL\Images\SHA256SUMS' "$base/SHA256SUMS"
& curl.exe -L --fail --retry 5 --proxy http://127.0.0.1:7897 --output "E:\WSL\Images\$name" "$base/$name"

(Get-FileHash "E:\WSL\Images\$name" -Algorithm SHA256).Hash.ToLower()
Get-Content 'E:\WSL\Images\SHA256SUMS' | Select-String $name
```

历史记录：340.2 MB，SHA256 为 `2a790896740b14d637dbdc583cce1ba081ac53b9e9cdb46dc09a2f73abbd9934`，与当时同源下载的 `SHA256SUMS` 一致。

校验范围：这是与 HTTPS 获取的同源摘要作比对，原记录没有独立验证 `SHA256SUMS` 的签名，不得表述为已完成 GPG 签名验证或独立来源认证。`current` 内容会变化，历史摘要不能直接用于新版镜像；应精确核对文件名及对应摘要，不能只计算哈希就认定校验通过。

### 4.5 配置软件源

原记录使用 Ubuntu 24.04 的 DEB822 配置位置 `/etc/apt/sources.list.d/ubuntu.sources`：

```text
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble-security
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
```

`Signed-By` 指定 apt 仓库签名校验使用的密钥环。仓库元数据签名及包哈希校验不同于 WSL MSI 的 Authenticode，也不同于手动比对根文件系统 SHA256；不得混称为同一种验证。不应关闭签名检查来绕过网络错误。

本地 secret 管理要求（建议，尚未配置验证）：

1. 将开发密码保存在经组织批准的本地密码管理器中，或在应用接入后使用开发用户范围的 .NET User Secrets；不要写入仓库、文档、日志、截图或共享配置。

3. 手工连接使用 `psql -W` 交互提示，不把密码写进命令行或 `PGPASSWORD` 示例。自动化若使用本地凭据文件，应置于仓库之外并严格限制访问权限（例如 Linux `.pgpass` 要求权限 `0600`），避免回显或记录内容。
4. 原文曾包含明文密码，应由有权限的人员按流程轮换，并评估既有副本或历史记录的泄露风险。**删除本文明文不代表密码已轮换或其他副本已清理；本次不访问、不验证、不修改任何凭据。**

5. **NuGet**：原记录 `api.nuget.org` 请求经重定向返回 200，华为云候选镜像 `https://repo.huaweicloud.com/repository/nuget/v3/index.json` 当次可达，清华与阿里云的所测路径返回 404。这些响应不等于所有包可还原；实际包还原证据仅见 Dapper 单次测试，镜像信任与使用政策另行确认。
6. **命令与脚本**：复杂引号可通过无凭据脚本减少解析问题；不要因此把密码写进脚本。示例脚本仅保存非敏感操作。
7. **开发工具链**：按整体设计逐项核查 Windows SDK、前端 Node.js / pnpm、EF Core 与业务功能；WSL .NET 10 安装结果不得替代 Windows 工具链确认。
8. **系统支持与合规**：核查 Windows 10 EOS / ESU、宿主及 WSL 补丁、代理和镜像使用政策、数据库暴露面。能安装、能连接不等同于合规。
