# 部门原型演示说明

> 这是交互原型，不是生产运维系统。界面中的资产、告警、工单、AI 输出及连接检查均为演示数据。具体可用范围以本轮验证记录为准。

## 建议评审顺序

工作台底部提供“部门评审建议路径”，按验收清单顺序给出可直接点开的步骤（设备接入 → 目标清单与预检 → 系统数据库 → AI 配置 → 提示词治理 → 后端联调 → 记录意见与结果）。该顺序只是建议，也不代表任何步骤已完成：每条结果仍需按包内 `case-records-template.csv` 人工记录并附证据，自动化检查不代填部门结论。

## 可选：本地数据保留模式（非生产）

默认启动脚本使用进程内内存存储，后端一重启数据即消失。若需要向部门演示“重启后数据仍在”，可用：

```powershell
& .\scripts\start-backend-persistent.ps1
```

它把四类数据写到 `artifacts/demo-data/`（`feedback.json`、`ledger.json`、`tasks.json`、`prompts.json`），删除这些文件即可回到初始种子。已实测：写入一条反馈（带幂等键）、批准一个任务、新增一个提示词草稿版本 → 重启后端 → 反馈仍为1条且同键重放返回200（未重复写入）、任务版本仍为2、提示词草稿版本与标记仍在，并且“存储模式（只读）”面板四项均显示“本机开发文件”。

必须同时说明其边界：这**不是生产持久化**——单进程、无事务、无并发写者、无多实例协调，两个进程写同一文件会丢失其中一次更新；接口契约仍报告 `persistence: none/memory`，就绪检查仍为 503，可持久化与生产就绪标记始终为否。该模式只用于演示“端口可替换”与“重启后重放仍被识别”。

## 可选：关系型模式（EF Core + SQLite，本地开发）

若需要向部门演示“数据库真的保证了什么”，可用：

```powershell
& .\scripts\start-backend-sqlite.ps1
```

它把**全部四个端口**（反馈、幂等台账、任务、提示词状态）指向 `artifacts/demo-data/demo.db`，并打印表名与重置方法（停止后端后删除 `demo.db`）。已实测：存储模式面板四项均显示“SQLite数据库（本地开发）”；写入带幂等键的反馈、批准任务 → **重启进程** → 反馈仍为1条、同键重放返回200、任务版本仍为2。

可以现场演示的数据库保证：**唯一索引**（台账按 `(Scope,Operation,Key)`、提示词按 `(PromptId,Version)`）拒绝重复写入；**事务**保证反馈插入与容量裁剪、任务状态与流水**同生共死**；**条件更新**实现 CAS（两个写入者竞争同一期望版本恰好一个成功）。

边界同样要说清：没有迁移历史、保留策略、行级安全或审计；数据库文件是本机开发用的；接口仍报告非持久化（`persistence: none/memory`），`/api/v1/storage-modes` 也始终把 `durable` 与 `productionReady` 标为否。它证明的是**端口与语义**可以落到真实数据库，而不是已经具备生产持久化。

## 异常与边界状态的手工演示路径

验收清单要求不能只演示正常态。下表给出在**打包评审包**（无后端）或本机联调环境下的手工路径；标“不可手工演示”的项目由自动化脚本或 xUnit 用例证明，评审时请如实记录为“未在本次手工演示”。

| 类别 | 手工路径 | 预期看到 |
| --- | --- | --- |
| 空数据 | 资产页搜索 `zzz`；或反馈页在无记录时查看列表 | 明确空态与下一步提示，不是空白页 |
| 未接入 | 用静态评审包（不启动后端）打开联调页并点任一“载入/检查” | 明确失败信息并保持禁用，**不回退为本地清单或成功** |
| 加载 | 点任一“载入候选/载入台账摘要”后立刻观察状态行；网络慢时更明显 | “正在载入…”且相关控件禁用 |
| 超时/取消 | 任一“载入/检查”进行中点击“取消…等待” | “等待已取消或超时；没有新的结论”，不产生成功结论 |
| 部分失败 | 设备接入页：选一个候选加入清单，再改协议为不匹配后加入第二项，点“检查清单” | “清单未通过：1/2 项符合目录规则”，并定位到第 2 项 |
| 过期 | 不可手工演示（需并发写入） | 由 `prototype-task-demo.mjs`、`prototype-feedback-tests.mjs` 证明旧版本/旧预览被拒 |
| 未知 | 任务状态模拟：创建→模拟批准→入队→开始→**确认超时**，再点“模拟核实成功/失败” | 先显示“结果未知”，对账后才落到成功/失败；期间不允许自动重试 |
| 不支持 | 不可手工演示（候选取值由服务端下发，界面无法构造枚举外取值） | 由 xUnit `DatabaseCapabilitiesTests`、`prototype-ai-preflight.mjs` 证明直接拒止并给出代码 |

其余面板级异常（503、响应结构不符、超大响应、慢响应、外部来源被拒）可在联调页配合停止后端或使用脚本复现，详见《部门原型验收清单》第 8 节。

## 安全边界

- 使用虚构演示数据，不录入真实员工信息、账号口令、设备密钥或生产配置。
- 原型不调用外部模型，也不连接真实设备；模拟连接成功不意味着真实连通。
- 数据库类型和厂商列表展示兼容规划，不代表所有选项已实现。
- 浏览器 localStorage 只用于模拟数据/意见暂存，不是共享数据库。不同浏览器或清空缓存后状态可能不同。
- 演示意见导出后由项目团队整理，不将自动测试结果冒充部门认可。

## 本机启动

已安装依赖时，在 Windows PowerShell 的项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-prototype.ps1
```

启动脚本优先使用本机 DSH 捆绑运行时；不存在时才使用 PATH 中的 Node.js/pnpm，不修改全局 PATH。请勿将依赖该私有运行时路径的脚本视为其他电脑的标准安装包。

标准可移植方式（Node.js ≥22.6，建议24 LTS；pnpm 11.7.0，与工作区构建许可配置匹配）：

```bash
cd src/frontend
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

本机演示入口预定为 `http://127.0.0.1:5173`。这不是使用部门其他电脑可访问的地址，不会自动修改防火墙或绑定全部网卡。

## 近期评审重点

- 每页顶部固定显示构建标识与数据模式：静态评审包的构建标识为提交短号（由构建脚本注入），本地开发则为构建时间（UTC）；同时声明“全部为模拟／Demo内存样本、未连接真实设备、数据库或模型”和固定观察时间。反馈中请引用该构建标识。

- 设备接入领域/关键词随URL保留，刷新可复现；关键词进入浏览历史，仅使用非敏感的厂商或协议名称。数据库监控目标不是平台自身数据库选型。
- 任务联调“读取模拟迁移记录”一次取得一致快照，更新状态与历史；与其他请求并发推进时仍使用版本冲突保护。错误响应禁用证据导出，需显式刷新。
- 联调错误不显示底层诊断正文，目录响应限制256KiB。AI与数据库预检只验证配置规则，可取消等待；取消不代表服务器回滚。
- 后端演示反馈成功后显示编号和时间，可点击“核对内存记录”只读核对。404可能表示重启丢失或容量淘汰，不代表从未保存；不要自动重提。编辑草稿清除旧回执并需重新确认。
- “刷新内存反馈”显示可读列表，支持按编号、正文、英文类别或页面本地筛选；重新读取会清空筛选。核对可取消等待，取消后未取得新结论。列表最多200条且仅进程内存，不能用于正式意见留档。
- 连接器只读意图预检只核对候选目录内协议与能力组合，含一组故意不匹配示例；通过不等于型号兼容、设备连通或允许执行，不需填写地址与凭据。
- “系统数据库”与“AI 配置”页可显式载入后端候选目录，查看依赖包声明、适配实现与实测验证状态；载入失败不回退本地说明，任何“已实现/已验证/可外连”声明为真都会被整批拒绝。
- 提示词治理的服务器版本区可查看只追加的版本历史与只读历史内容；保存与恢复各占一个名额，达到20后均被拒绝且无自动淘汰。发布按钮只把当前草稿复制成一条不可变发布修订（同一草稿版本只能发布一次），不调用模型、不代表审批或上线，发布修订内容可只读核对。
- 静态评审包不包含后端服务，上述真实HTTP联调必须按下面步骤启动本机Demo。静态包的接口不可用提示不是设备连接失败。
- 需要先“载入”才能提交的面板：AI 预检的协议、数据库预检的候选取值、设备接入的候选目录。理由是不让界面自行猜测协议或数值；未载入时相关按钮即为禁用，载入失败不会退回本地清单。
- 各页与验收清单 case 的覆盖/排除对照见《原型范围与case映射》，该表由脚本校验，不会与代码中的路由清单漂移。
- 预检结论旁会给出后端声明的原始事实：连接器显示该候选已登记协议、规划能力与“接入前需确认”清单，数据库显示所选候选的必测清单与依赖包状态。它们用于对照差异，不代表兼容、连通或已完成验证。AI 协议清单还可“预览请求形状”，用于核对将要发送的载荷是否只含合成内容。
- 连接器可把多个候选加入“拟接入候选清单”后一次性检查（最多20项），失败项按第N项定位；联调页可查看操作幂等台账摘要并按操作ID对账。台账仅进程内存、重启丢失，查询只用于对账、不会重放操作。
- “本次会话评审证据”面板同时出现在联调页与验收反馈页：它汇总本次会话中已由后端确认的结论，可导出 JSON 附在反馈里；不含提交正文、凭据与设备地址，应用内切页共享、整页刷新清空，不能作为生产或验收证明。
- 每页底部都有“记录本页意见”：写入与验收反馈页同一份本机数据，提交后不跳转、页面筛选保持；它不提交后端、不发送通知，也不代表部门签认。含密码、密钥等疑似敏感内容时会被拒并保留草稿供修改。

## 后端联调（可选）

先在另一个 PowerShell 窗口执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-backend.ps1
```

它使用已安装的 WSL Ubuntu-24.04 启动固定 `localhost:5094` Demo API；不连接数据库、不执行设备操作。前端“后端联调”页点击才访问API，不会在打开原型时自动请求。

Vite开发服务将同源 `/api` 和 `/health` 代理到本机后端；后端内存反馈与浏览器本机反馈不共享。静态生产构建/preview不具备该开发代理，部署时联调页可能不可用，不会因此偷偷使用本地假成功。

本机可运行 `scripts/verify-prototype.ps1` 统一构建和自动检查，运行前需要前后端开发服务均启动。测试仅生成虚构内存反馈，进程重启清空。

## 向使用部门交付

首选共享屏幕或由专门演示机器操作。需要多电脑访问时，后续在经批准的内网演示服务器部署前端静态构建，配置 HTTPS、访问控制和模拟数据提示，不直接暴露开发服务器到公网。

```bash
cd src/frontend
pnpm build
```

构建输出目录 `src/frontend/dist` 可交给静态站点服务器；如使用路径路由，需配置回退到 index.html。是否离线打开支持由实际构建验证决定，不建议双击 HTML 文件作为交付方式。

### 静态演示包

构建并检查通过后，可在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-prototype.ps1
```

包写入忽略目录 `artifacts/packages`，包含静态资源、演示限制说明和来源提交清单，并输出 ZIP 的 SHA256。清单记录是否存在未提交变更。它不包含后端、密钥、数据库或开发代理，也不提供认证；需部署在批准的隔离演示环境。打包成功不等于部署或部门验收成功。

演示包内附独立本机静态服务脚本（需要Node.js 24）。解压后在包目录执行：

```bash
node serve-demo.mjs --root . --port 5175
```

打开 `http://127.0.0.1:5175/`。此服务只绑定回环地址，不提供身份认证或生产部署能力；缺失API返回明确JSON 503，服务器提示词/联调操作会显示不可用，不以HTML回退伪造成功。主业务本地模拟仍可使用。

## 任务状态模拟

开发版的后端联调页可创建内存模拟任务，演示批准、排队、运行、超时待核实和确认结果。所有按钮都是状态演示，不是真实审批/命令执行。请求失败后先刷新已有任务确认状态；取消等待不保证回滚。刷新页面丢失当前任务引用，重启后端清空全部任务，容量100条。静态包没有后端，创建返回不可用属预期，不会改为假成功。

### 建议任务评审步骤（须本机后端）

1. 创建模拟任务，依次模拟批准、排队、开始、超时；确认显示“结果未知”，没有直接重试按钮。
2. 模拟核实成功，读取模拟迁移记录，核对5条记录和最终版本6。记录没有操作者和时间，不是生产审计日志。可“导出模拟任务证据”下载JSON，附到评审反馈；文件明确标注模拟、内存、未执行，不能作为真实操作审计证明。
3. 成功/失败/取消终态可“结束本次查看”再创建下一任务；只清除页面引用，不删除服务器历史或释放100条容量。
4. 遇到409、响应不完整或网络错误，先刷新任务核实，再继续；不允许错误后继续使用旧状态。取消等待同样不代表服务器回滚。
5. 静态包不提供以上后端状态能力。使用部门仍可离线评审17页主业务模拟、反馈导入导出和本地提示词治理；不能把静态包503当成真实后端验收。

## 连接器规划评审

设备接入页可按厂商、协议、规划能力搜索，并与领域筛选取交集；“清空连接器筛选”恢复全部。搜索无结果仅代表当前规划表没有匹配项，不代表产品已确认不支持。当前0个真实连接，厂商列是候选示例，不是兼容认证。

## 离线配置规则评审（须本机后端）

联调页的数据库预检可比较PostgreSQL配置与SQLite多实例拒绝结果；AI预检可比较正常预算与预算小于输出token的拒绝结果。两者仅校验配置规则，不保存、不读取密钥、不发起目标数据库或模型连接。虚构地址/凭据引用固定；规则通过不等于网络可用、模型兼容或生产就绪。修改输入后旧结论清除，需重新显式检查。静态包相关操作不可用属预期。

## 评审方法

1. 先说明模拟模式以及“未接生产”的范围。
2. 按部门验收清单操作资产、告警、工单、配置及提示词流程。
3. 记录页面、复现步骤、期望行为、优先级及部门角色；不要写真实密码。
4. 可按部门、状态、优先级和关键词组合筛选反馈；“清空反馈筛选”恢复全部列表。导出JSON始终包含全部反馈，不仅是当前匹配项。导出后进入待处理列表，开发修复后对原步骤回归。
5. 每次展示保留对应 Git 提交编号，避免不同版本反馈混在一起。
