# 企业 IT 日常运维工具平台——初步想法

> 文档性质：需求构想与讨论草案，不代表已经确定的技术方案。
> 2026-10-10 更新：现已选定 Web 方向；最终技术与设计基线见 [整体系统设计方案](整体系统设计方案.md)，本文件保留早期需求背景。实际变更见 [更新日志](更新日志.md)。
> 目标：围绕企业现有 IT 环境，建设统一运维工作台，并加入可控、可追溯的 AI 辅助能力。

## 一、背景与现有环境

目前已知企业环境包括：

- 网络防火墙。
- 上网行为管理系统。
- 三层交换机。
- 集中杀毒软件系统。
- Windows AD 域环境。
- 共享文件服务器。
- 打印机共享与打印服务。
- 虚拟化环境。

尚待确认：设备品牌和版本、员工及设备规模、分支机构情况、现有监控与备份系统、可用接口、部署资源，以及企业对 AI 使用和数据外发的要求。

## 二、产品定位

建设一套面向企业 IT 管理员日常使用的“企业 IT 运维工作台”。

不替代现有防火墙、行为管理、杀毒、AD 和虚拟化平台，而是统一汇总其资产、状态、告警、常用操作和处理记录，减少在多个管理后台之间反复切换。

围绕五个问题展开：

1. **有什么：** 设备、系统、账号、授权、业务用途和负责人清楚可查。
2. **哪里异常：** 及时发现网络、服务器、共享、打印、防护和备份问题。
3. **如何处理：** 提供诊断工具、操作手册和安全的重复任务执行能力。
4. **做过什么：** 工单、权限调整、配置变更和运维操作可追溯。
5. **AI 能帮什么：** 辅助查询、解释、分析、编写和总结，但不越权代替管理员决策。

### 建设原则

- 先只读查询与监控，再受控操作，最后考虑跨系统自动化。
- 先解决高频、耗时、影响大的问题，不追求第一版功能齐全。
- 优先复用现有平台和成熟组件，重点定制统一入口与企业内部流程。
- 自动发现与人工维护结合，允许记录“未知”“未采集”“待确认”。
- 所有有副作用的操作均需明确权限、目标、影响和审计。
- AI 是辅助入口，不是绕过权限和审批的超级管理员。

## 三、主要使用者与典型场景

### 使用者

- IT 管理员：日常巡检、故障处理、账号管理、设备维护。
- IT 负责人：查看风险、容量趋势、工单和工作报告。
- 部门负责人或审批人：确认权限申请、账号流程和业务影响。
- 普通员工（后续可选）：报修、查看处理进度、查询自助知识库。

### 典型日常流程

1. 上班打开工作台，查看核心服务状态、昨夜备份、关键告警和待办。
2. 员工反馈故障，通过姓名、主机名、IP 或资产编号查询关联信息。
3. 使用诊断工具采集证据，AI 辅助整理可能原因与排查步骤。
4. 对需要变更的操作进行确认或审批，通过受控工具执行。
5. 将处理过程沉淀到工单、知识库和巡检报告中。

## 四、功能模块规划

### 4.1 统一首页与工作台

首页优先展示需要处理的事项，而不是单纯堆积图表。

- 当前紧急告警与影响范围。
- 核心系统健康状态与采集时间。
- 今日待办、待审批事项和未关闭工单。
- 昨夜备份结果、容量风险和证书/维保到期提醒。
- 账号锁定、终端防护异常、打印队列异常等快捷入口。
- 全局搜索：资产、IP、主机名、用户、工单、知识库。
- AI 助手入口及有依据的每日运维摘要。

### 4.2 统一资产台账

| 类别 | 建议管理的信息 |
| --- | --- |
| 网络设备 | 类型、品牌、型号、管理 IP、位置、固件、维保日期 |
| 服务器 | 物理/虚拟、操作系统、资源配置、业务用途、负责人 |
| 员工电脑 | 使用人、部门、主机名、IP、序列号、域和杀毒状态 |
| 打印设备 | IP、型号、位置、共享队列、驱动、耗材状态 |
| 软件与授权 | 许可数量、订阅、证书、续费与到期时间 |
| 资源关系 | 虚拟机与宿主机、业务与服务器、终端与交换机端口的关联 |

要求：

- 支持手工录入、表格导入以及通过接口同步。
- 使用稳定资产标识，不能仅以 IP 判断是否为同一资产。
- 自动同步数据与人工维护字段明确归属，避免相互覆盖。
- 保留来源、最后同步时间、变更记录和退役状态。

### 4.3 统一监控与告警

| 对象 | 关注内容 |
| --- | --- |
| 防火墙 | 在线状态、CPU/内存、接口流量、连接数、VPN、HA（如有） |
| 行为管理 | 系统状态、策略变更、安全与违规事件摘要 |
| 三层交换机 | 上联、端口利用率、错误包、丢包、CPU/内存、链路异常 |
| Windows 服务器 | CPU、内存、磁盘、关键服务、事件日志 |
| AD | 域控可用性、复制、DNS、时间同步、账号锁定异常 |
| 文件服务 | 容量、共享可用性、备份结果、关键访问事件 |
| 打印服务 | 后台处理服务、队列积压、打印机离线 |
| 虚拟化 | 宿主机、虚拟机、集群、存储容量、快照与资源压力 |
| 杀毒平台 | 客户端离线、防护关闭、病毒库过期、未处理威胁 |
| 备份 | 最近成功时间、失败任务、存储容量、恢复验证结果 |

告警机制：

- 分级、去重、聚合、维护窗口及依赖抑制。
- 支持企业微信、钉钉、邮件等通知渠道，按实际环境选择。
- 状态闭环：新告警 → 已确认 → 处理中 → 已恢复/关闭。
- 关联资产、负责人和工单。
- 明确区分正常、异常、采集失败、数据过期。

具体指标取决于厂商、版本和授权能力，不能预设全部设备均支持。

### 4.4 AD 账号与员工入转离

**日常管理：**

- 查询账号、OU、部门、组成员关系、禁用和锁定状态。
- 查询密码到期情况、长期未使用账号和电脑对象。
- 在日志具备的前提下分析账号反复锁定来源。
- 受控解锁和密码重置，按策略要求下次登录修改。
- 监测高权限组成员变化。

**入职：** 按模板建号、放入 OU、加入岗位授权组、分配资源、生成设备领用任务。

**调岗：** 对比新旧权限，移除旧岗位不再需要的权限，记录审批与生效时间。

**离职：** 按流程禁用账号、回收组权限和 VPN 等访问、回收设备、交接数据，并按保留政策处理账号及目录。

注意：禁用 AD 账号并不保证立即终止所有既有会话或第三方访问，需单独识别和处理相关环节。密码不得进入普通日志或 AI 上下文。

### 4.5 共享文件与权限管理

- 共享目录台账、用途、所属部门和业务负责人。
- 查询共享权限、NTFS 权限、继承关系和组嵌套关系。
- 辅助回答“某人为什么有权限”“哪些人可能可以访问”。
- 排查过宽授权和异常继承。
- 权限申请、审批、开通、到期复核与回收。
- 容量趋势、配额、空间不足提醒。
- 误删恢复申请与处理记录。
- 在已启用相关审计策略的范围内查询关键访问事件。

原则：优先通过 AD 安全组授权，减少直接给个人授权。有效权限判断需考虑共享权限、NTFS、拒绝项、组嵌套等因素，复杂情况应标记需进一步验证，不能仅凭一张 ACL 表直接下结论。

### 4.6 网络诊断与 IP 地址管理

**工具箱：** Ping、路由跟踪、DNS 解析、TCP 连通性检测、不同网络节点的业务探测。

**关联查询：** IP、MAC、主机名、使用人、交换机接入端口、VLAN、端口状态和错误计数。

**地址管理：** 网段、VLAN、网关、用途、静态分配、保留地址、已用/空闲/待确认状态、变更记录；如有 DHCP 则对接租约信息。

**配置管理：** 网络设备配置备份、版本对比、关键策略变更与到期复查。

限制：探测失败不等于地址空闲；IP 冲突提示需有证据验证。初期不自动下发网络策略。探测和诊断应限定已授权网段、目标及速率，避免形成任意网络访问入口。

### 4.7 集中杀毒与终端健康

- 汇总客户端覆盖率、离线状态、病毒库、防护状态和未处理威胁。
- 结合资产台账及 AD 清单发现疑似未安装客户端的终端。
- 关联使用人、部门、感染历史和处置记录。
- 在厂商支持时，后续加入受控扫描、隔离和解除隔离。

原则：复用现有杀毒系统，不重新开发防病毒引擎。隔离等操作须评估业务影响并授权确认。

### 4.8 虚拟化与服务器管理

- 汇总宿主机、集群、虚拟机与存储资源。
- 关联业务负责人、资源配置、网络和备份。
- 展示资源趋势、容量压力和平台告警。
- 提醒长期关机、疑似闲置虚拟机，以及过久或过大的快照。
- 管理新建、扩容、下线申请。
- 后续提供受控开关机、重启和资源变更。

注意：快照不是备份；不能仅因资源利用率低就自动关机、删除或回收。变更前需确认依赖、备份与维护窗口。

### 4.9 打印服务管理

- 打印机、共享队列、位置、部门、驱动清单。
- 在线状态、耗材和卡纸状态（设备支持时）。
- 队列积压和打印后台处理服务监控。
- 定位具体异常队列与作业，授权后取消或清理。
- 驱动安装说明与常见问题知识库。

优先精确处理异常作业，不提供默认清空所有队列的危险快捷操作。

### 4.10 备份与恢复管理

- 汇总 AD、文件服务器、关键服务器、虚拟机及网络配置备份。
- 监测失败、连续失败、长时间未成功和备份存储不足。
- 记录备份策略、保留周期、恢复负责人。
- 记录业务恢复时间目标（RTO）和可接受数据丢失范围（RPO）。
- 建立恢复演练计划、执行记录和验证结果。

必须同时关注“最近成功备份”和“最近恢复验证”。工作台以汇总和管理为主，优先对接现有备份产品，不默认自研完整备份引擎。

### 4.11 工单、巡检与知识库

**工单：** 故障、权限、设备及变更申请；支持分类、优先级、负责人、处理记录、附件和资产关联。

**巡检：** 定期检查 AD、网络、磁盘、备份、杀毒等，生成正常/异常/未采集的结果；异常可转工单。

**知识库：** 故障手册、系统依赖、拓扑说明、安装配置、应急恢复、维保联系方式。

**报告：** 日报、周报、告警趋势、重复故障、容量风险及工作量统计。

### 4.12 自动化任务中心

- 将验证过的脚本封装为有名称、有参数、有授权要求的操作模板。
- 支持任务计划、人工触发、运行记录、超时、重试和结果查询。
- 批量操作先预览目标与影响，限量、分批，必要时失败停止。
- 可恢复操作提供明确恢复步骤；不可逆操作必须特别标记。
- 对失败或状态未知的变更先核实结果，避免盲目重试造成重复操作。

## 五、AI 辅助功能设计

### 5.1 定位与边界

AI 作为运维助手，主要负责自然语言查询、证据整理、排障建议、知识检索、草稿生成和报告总结。

初期仅提供只读辅助。后续如接入操作能力，AI 只能提出结构化操作建议，由平台校验权限、参数和审批后，通过受控工具执行；不得直接获得任意 Shell 或无限制管理权限。

### 5.2 AI 场景清单

| 场景 | 示例 | 预期输出与边界 |
| --- | --- | --- |
| 自然语言查询 | “哪些服务器磁盘剩余不足 15%？” | 调用已授权查询接口，返回对象、指标、采集时间和来源 |
| 运维知识问答 | “员工无法访问部门共享，应该先查什么？” | 检索内部手册，引用来源并给出适用前提 |
| 故障辅助诊断 | “这台电脑能上网但访问不了共享” | 整理现象，提出检查顺序，区分事实与猜测 |
| 告警关联分析 | “为什么同时出现这么多设备离线？” | 根据时间、拓扑和事件提供可能共同原因，不冒充已确认根因 |
| AD 锁定分析 | “这个账号为什么反复锁定？” | 在授权范围内关联锁定日志与主机线索，说明证据缺口 |
| 权限解释 | “这个用户为什么有目录访问权限？” | 解释组、继承与权限路径，必要时提示有效权限待验证 |
| 日志辅助解读 | “这些事件是否需要处理？” | 摘要、分类、时间线、可能原因和下一步建议 |
| 巡检报告 | “总结今天的异常和待办” | 根据真实巡检数据生成带来源的摘要，不将缺失数据写成正常 |
| 工单辅助 | “把这次处理过程整理成工单” | 生成标题、分类、现象、处理过程和解决结果草稿 |
| 知识沉淀 | “将已解决工单整理成操作手册” | 脱敏后形成待审核草稿，不直接发布未经验证的经验 |
| 脚本辅助 | “写一个检查关键 Windows 服务的脚本” | 解释参数、权限、风险和测试方式，默认不执行 |
| 变更辅助 | “这个网络配置改动可能影响什么？” | 对比差异，结合已知依赖列出风险与验证清单 |
| 容量分析 | “文件服务器是否需要扩容？” | 基于历史数据给出趋势、估计区间及数据限制 |
| 员工自助（后续） | “怎样连接部门打印机？” | 仅检索面向员工开放的文档，复杂问题引导报修 |

### 5.3 建议的 AI 交互流程

1. 用户提出问题，平台确定用户身份及权限范围。
2. AI 识别意图，必要时询问目标、时间范围和影响范围。
3. 通过只读接口或知识检索获取允许访问的数据。
4. 输出“已知事实、来源、可能原因、缺少的信息、建议下一步”。
5. 如需要变更，生成操作预览，包括目标、参数、影响、前置条件和恢复方案。
6. 由平台进行授权校验及必要审批，管理员确认具体操作。
7. 由受控任务执行器执行，保存结果与审计，AI 再辅助总结。

示例：

> 管理员：“帮我看看昨晚为什么有很多服务器离线。”
>
> AI：查询对应时间段的监控、链路与设备事件，整理时间线，说明是否存在共同上联故障的证据，列出仍需验证的事项；不会直接重启交换机或修改防火墙策略。

### 5.4 AI 数据来源

- 授权范围内的资产台账与关联关系。
- 监控指标、告警、事件和采集状态。
- 工单、巡检、变更和恢复演练记录。
- 审核过的内部知识库和操作手册。
- 按需获取并脱敏的日志片段。
- 受控接口查询到的 AD、共享、网络、虚拟化等实时信息。

知识文档应保留版本、适用产品/版本、负责人、审核时间和访问权限。检索结果必须继承原始文档权限，不能因为被纳入 AI 知识库就变成全员可见。

### 5.5 AI 安全与可信要求

- **权限不扩大：** 查询、检索、工具调用和执行均在服务端校验当前用户权限，不能只靠提示词约束。
- **敏感信息最小化：** 密码、密钥、令牌不得发送给模型；个人信息、文件路径和业务信息按需脱敏。
- **外发需合规：** 是否使用外部模型 API、可发送的数据类别及保留政策须经企业确认。
- **防范提示注入：** 日志、网页、工单和文档均视为数据；其中出现的操作指令不得覆盖平台规则或触发执行。
- **提供依据：** 尽量引用具体资产、事件、指标时间和文档版本；证据不足时明确说明。
- **不虚构结果：** 建议、执行计划和实际执行结果分开展示，未执行不能写成已处理。
- **操作审批：** 不允许 AI 自行批准操作；确认须绑定具体目标和参数，过期或改变后重新确认。
- **审计与保留：** 记录必要的调用、工具参数与结果，日志脱敏，设置保留周期和访问控制。
- **可用性隔离：** AI 不可用时，资产、监控、工单及人工操作仍可使用。
- **质量验证：** 上线前覆盖错误建议、越权检索、提示注入和危险操作等测试场景。

### 5.6 模型部署选择

| 方式 | 优点 | 需要评估 |
| --- | --- | --- |
| 本地模型 | 数据可留在企业环境，便于控制访问范围 | 硬件、效果、运行维护成本及更新机制 |
| 企业认可的外部模型 API | 接入相对方便，可选模型较多 | 数据外发、合同条款、网络可用性、调用成本 |
| 混合模式 | 按数据敏感度和任务类型选择模型 | 路由、脱敏、权限和审计实现更复杂 |

暂不确定最终方案，先确认企业安全政策，再做小范围效果与成本验证。本地部署也不等于天然安全，仍需隔离、授权和审计。

## 六、建议页面结构

```text
运维工作台
├─ 首页 / 今日待办
├─ 资产中心
│  ├─ 网络设备
│  ├─ 服务器与虚拟机
│  ├─ 员工终端
│  ├─ 打印设备
│  └─ IP / VLAN / 授权与维保
├─ 监控与告警
├─ AD 与账号管理
├─ 文件共享与权限
├─ 网络诊断
├─ 终端安全
├─ 虚拟化管理
├─ 打印管理
├─ 备份与恢复
├─ 工单与变更
├─ 巡检与报告
├─ 知识库
├─ 自动化任务
├─ AI 助手
```

以上是功能归类，不要求第一版全部建成独立菜单，低频功能可以合并。

## 七、整体技术形态设想

采用“内网 Web 工作台 + 后台服务 + 采集/执行节点 + 现有管理平台”的结构。

- **Web 工作台：** 提供看板、查询、工单、审批、任务和 AI 对话。
- **后台服务：** 负责权限、资产、告警、流程、审计和统一接口。
- **连接器：** 适配不同厂商、版本和协议。
- **采集节点：** 按网络区域采集信息，减少不必要的跨网段管理访问。
- **执行节点：** 使用受限身份执行批准的操作，与只读采集权限分开。
- **任务调度：** 负责定时采集、巡检、报表和自动化任务。
- **数据存储：** 根据数据类型保存业务数据、指标、日志和文档，不预设全部塞进一种数据库。
- **AI 服务层：** 统一处理模型接入、知识检索、工具调用、脱敏和审计。

可能的接入方式包括 SNMP（优先评估 SNMPv3）、Syslog、厂商 API、AD/Windows 管理接口、PowerShell、WinRM 及受控 SSH，具体视产品支持情况决定。

若已有 Zabbix、PRTG 或其他监控系统，优先集成；未有时评估成熟监控底座，不默认从零重写。暂不锁定开发语言、前端框架、数据库及模型供应商。

## 八、安全与治理基础

1. 对接企业身份体系，平台角色与 AD 管理权限分开设计。
2. 查看、运维、审批和平台管理分权，高权限访问尽量启用 MFA。
3. 默认最小权限，不把域管理员作为所有连接器的通用账号。
4. 凭据进入受控的加密存储或凭据管理系统，不放在代码、前端和普通日志中。
5. 使用 HTTPS，并限制管理入口与执行节点的网络访问范围。
6. 对敏感操作记录人员、时间、对象、参数摘要、审批、结果与关联工单。
7. 操作模板、连接器和知识库均需要版本管理及审核机制。
8. 批量和高风险操作提供预览、审批、维护窗口、限流和验证步骤。
9. 行为管理与文件访问日志按需采集，明确用途、访问角色及保留期限。
10. 对平台自身的数据、配置和必要密钥制定备份与恢复方案。

## 九、分阶段建设建议

### 第一阶段：最小可用版本（MVP）

目标：先做到看得见、查得到、能告警、能留痕，AI 能提供有依据的只读帮助。

- 登录、基础角色权限与操作审计。
- 资产台账、导入、负责人管理和全局搜索。
- 核心设备在线状态、服务器磁盘和关键服务监控。
- 基础告警通知与处理闭环。
- 备份结果汇总；接口不具备时先支持人工登记并明确来源。
- AD 账号只读查询、网络诊断工具箱。
- 每日巡检、轻量工单、初步知识库。
- AI 知识问答、只读查询、巡检摘要和故障分析建议。

不纳入 MVP：任意远程命令执行、全自动入转离、AI 自主改配置、自动隔离终端或重启生产设备。

### 第二阶段：受控操作与深度对接

- 对接杀毒、虚拟化、行为管理及打印系统。
- AD 解锁、密码重置等授权操作。
- 文件权限申请与审批。
- 网络配置备份与版本对比。
- 受控自动化任务、员工入转离任务清单。
- AI 日志分析、告警关联、工单草稿与变更风险提示。

### 第三阶段：流程自动化与优化

- 经验证的入转离跨系统流程。
- 权限到期回收、定期复核。
- 容量趋势与资源优化建议。
- 员工自助入口和更完善的报表。
- AI 提出操作计划，经授权审批后调用白名单工具执行。
- 持续评估知识问答与诊断质量，优化错误和无依据回答。

不预设具体工期，待规模、接口条件和开发资源明确后再估算。

## 十、初步验收方向

后续应按企业实际情况确定具体目标值，现阶段先明确验证方式：

- 能通过用户、主机名或 IP 找到资产、负责人和关联信息。
- 核心告警能通知、确认、关联工单并记录恢复。
- 采集失败不会被显示成正常。
- 备份成功记录与恢复验证记录能够分别查询。
- 敏感操作可查到执行人、授权过程和实际结果。
- 不同角色不能看到或操作超出权限的资源。
- AI 回答能说明来源和数据时间，证据缺失时不编造。
- AI 无法读取未授权文档，也无法通过日志中的指令触发执行。
- 模型服务不可用时，核心运维功能仍可正常工作。

## 十一、范围外或暂缓事项

- 自研防火墙、杀毒引擎、虚拟化平台或完整备份引擎。
- 从零开发覆盖全部厂商和协议的监控系统。
- 无审批的网络策略下发、批量删除账号、删除虚拟机或数据。
- 无限制远程终端和由 AI 自由生成后直接执行的命令。
- 未经审核向外部模型上传企业全量日志、文件或配置。
- 一开始建设完整复杂 ITSM、采购财务或全生命周期 ERP。

## 十二、需要进一步确认的问题

1. 企业人数、终端数量、服务器及网络设备数量是多少？
2. 是否有多个办公地点、分支、隔离网段或跨域环境？
3. 防火墙、行为管理、交换机、杀毒及虚拟化分别是什么品牌和版本？
4. 是否已有监控、备份、工单、资产管理系统，是否提供 API？
5. 当前最耗时、最常发生、风险最高的三类工作分别是什么？
6. 主要由一位管理员使用，还是需要多人协作、审批和员工自助？
7. 希望优先做统一查询告警，还是账号、共享、打印等操作工具？
8. 企业允许使用外部 AI API 吗？哪些数据禁止外发？
9. 是否具备本地模型运行资源？可接受的成本和响应速度是多少？
10. 有哪些开发和维护资源，预期部署在 Windows 还是 Linux 环境？
11. 审计日志、工单、行为记录及 AI 对话需要保留多久？
12. 是否已有关键业务的恢复目标、变更审批和维护窗口制度？

## 十三、当前建议结论

优先建设：

**统一监控 + 资产台账 + AD 查询工具 + 备份巡检 + 网络诊断 + 轻量工单/知识库 + AI 只读辅助。**

先用这套组合解决每天的真实问题，再逐步加入权限流程、受控操作和跨系统自动化。AI 应从“能解释、能找资料、能总结”起步，再发展到“能提出有依据的操作计划”，不以直接接管生产系统为目标。
