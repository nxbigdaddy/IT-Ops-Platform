# 扩展兼容与 AI 配置设计

> 版本：v0.1；日期：2026-10-10。**本文是目标设计与实施门禁，不是已实现、已连通或已验证清单。**
> 依据：[整体系统设计方案](<整体系统设计方案.md>)。本文补充前端优先交付、多环境兼容、平台数据库 provider 与 AI 配置，不撤销原方案的授权、审批、任务、审计和只读优先约束。
> 初次编写仅为设计，未核验真实数据库、设备或外部模型。后续实现进展见更新日志：第7轮已有统一DatabaseCapabilities目录与离线部署草稿预检，Demo API从该目录生成；第8轮建立10类ConnectorRegistry候选元数据并用于Demo目录；仍无任何真实数据库/设备适配或连通验证。文中的默认值为建议初值，测试与企业政策确认后才可成为承诺。

## 1. 交付次序与范围边界

1. **前端优先可交使用部门**：先交可独立运行、导航完整、核心场景可操作且明确标识模拟数据的部门评审原型；同时建设 API 合同、数据库、连接器、权限与测试。原型用于流程体验与反馈，不以它处理生产变更或保存真实秘密。
2. 两条交付线分开：原型可体验→获准只读真实试点→生产上线。每次发布说明数据来源模式、真实能力、限制及验证证据。原型页面“保存/测试/执行”如为模拟，结果必须带“模拟，未写入服务器/未访问目标”。
3. 前端数据层按合同接入 fixture/mock 与真实 API，页面不自行拼接设备协议。模拟模式显著标识；真实请求失败不能静默替换成模拟成功。
4. 兼容性、AI 和后台工作并行推进，不因等设备、凭据或外发审批阻塞原型。缺少批准时采用脱敏合成样本、关闭外发、只读降级；不得把“持续推进、不需参与”解释为代替企业批准或伪造部门验收。
5. 每个迭代形成“需求→设计/实现→检查→证据→缺陷→复测→发布说明”闭环。未决项入台账，自动化可持续完成编码检查与回归；生产接入、数据外发、高风险操作、正式验收保留授权门禁。

## 2. 平台数据库与监控目标数据库必须分开

| 维度 | 平台数据库 provider | 监控目标数据库连接器 |
| --- | --- | --- |
| 用途 | 保存平台资产、工单、权限、审计、持久任务等业务事实 | 读取业务数据库的可用性、容量、复制、备份等批准指标 |
| 配置入口 | 部署配置/管理员只读诊断页；生产切换走迁移流程 | 连接器页按资源范围和节点注册 |
| 凭据 | 平台运行、迁移、备份身份分离，服务端 secret 引用 | 每个目标独立只读监控身份，限定视图/系统目录 |
| 扩展关系 | 安装相应 EF/provider 与迁移包，满足完整测试门禁 | 可独立支持 PostgreSQL、SQL Server、MySQL 等目标 |
| 严格禁止 | 网页随意改连接串后热切换、生产失败自动切 SQLite | 任意 SQL 编辑器、默认读取业务表正文、把目标账号当平台账号 |

例如平台使用 PostgreSQL 仍可监控 SQL Server；实现 MySQL 监控连接器不等于平台可运行于 MySQL。两套能力清单、凭据权限、健康状态和证据分别展示。

### 2.1 平台 provider 测试能力矩阵（初始全部未验证）

`planned`=目标与合同待实现；`implemented`=代码及可复现测试存在但未完成声明环境验证；`verified`=指定版本/部署组合通过所有必需门禁并有报告。当前表的 planned 不宣称已有实现；依赖包存在不提升状态。

| 候选 | 定位/版本策略 | 必测能力与差异 | 初始状态/放行条件 |
| --- | --- | --- | --- |
| PostgreSQL 16 | 首发生产基线；记录实际受支持补丁、EF/Npgsql 版本 | schema、UUID、UTC 时间、inet/cidr、JSONB、并发版本、SKIP LOCKED、Outbox、全文及可选向量 | planned；完成首发全套集成、恢复、负载门禁才可 verified |
| SQL Server | 企业候选；具体引擎/版本/兼容级别待测试锁定 | schema、uniqueidentifier、datetimeoffset、JSON 差异、锁提示/隔离级别、死锁、全文索引/语言分词 | planned；不能以“EF 可连接”替代任务竞争、迁移、恢复测试 |
| MySQL | 企业候选；具体受支持版本待锁定，MariaDB 单列不得自动等同 | 无等价多 schema 隔离策略、UUID 编码、排序规则、JSON、事务引擎、锁与隔离、全文分词 | planned；独立 migration、表名前缀/库隔离方案和并发门禁通过 |
| SQLite | 候选本地演示/受限单实例；记录 SQLite 及 provider 版本 | 无服务器任务锁、写竞争/WAL、约束与 ALTER 限制、UTC 编码、备份一致性、可选 FTS 扩展 | planned；不作为默认生产 HA/多 Worker 方案；未达功能要求应明确禁用能力 |

每一组合记录 `providerVersion / engineVersion / extensionVersions / deploymentTopology / testSuiteVersion / executedAt / evidenceRef / limitations`。矩阵按能力分别记录 passed/failed/not-run/not-applicable，not-run 不能计为通过。版本升级、拓扑变化或关键扩展变化触发重测。UI 显示“候选/未验证”，不得把所有候选展示为“已支持”。

共同放行测试至少包括：空库初始化、旧版升级、唯一/外键/大小写/空值语义、UTC 与夏令时边界、分页稳定排序、乐观并发、事务回滚、Outbox/Inbox 去重、双实例任务领取与租约 fencing、进程崩溃恢复、备份恢复、权限过滤、批量导入、保留清理及预期峰值两倍负载。SQLite 单实例限制必须在服务端启动检查，不仅在 UI 提示。

### 2.2 差异隔离接口

- `IPlatformStoreCapabilities`：描述实际 schema、全文、向量、分区、锁等能力，业务按显式能力降级或拒绝启动；不得悄悄改变一致性。
- `IDatabaseDialect`：只由基础设施实现参数化 SQL、标识符、分页、JSON/网络地址查询等差异，业务模块不拼 provider 名或任意 SQL。PostgreSQL 专用类型在其他 provider 中由规范化值对象映射，跨库迁移验证精度与排序。
- `ITaskLeaseStore`：原子领取、续租、租约令牌/fencing、完成写入、重试与 Unknown 核实。各实现采用数据库支持的锁/事务，返回同一状态语义；不能以进程内互斥替代跨实例唯一领取。
- `IOutboxStore`：业务变更与发件箱同事务；消费者幂等。跨 provider 都通过提交前后崩溃测试。
- `ITextSearch` / `IVectorSearch`：分词、排名、索引、向量维度/距离和 ACL 前置过滤隔离。向量可采用受控独立索引或明确禁用；SQLite FTS、PostgreSQL 全文及其他全文实现不承诺结果逐字相同。禁用向量时保留授权关键词检索并标明质量差异。
- `IMigrationRunner` / `IBackupRestorePlan`：provider 专属迁移与备份流程，不能复用 PostgreSQL migration 直接执行于其他引擎。EF 模型缓存按 provider 区分；CI 针对每一允许组合运行真实数据库，不用内存数据库证明关系/锁语义。

### 2.3 配置和切换运行手册

目标配置仅包含 `Database.Provider`、`ConnectionSecretRef`、`MigrationSetVersion`、`DeploymentMode`。连接串与口令不返回浏览器；管理员页只能看到 provider、脱敏端点、版本、健康与最近验证。运行服务不得随意拥有建库/迁移权限。

**provider 切换不是热切换，也不是简单修改下拉框。** 必须按维护窗口实施：

1. 生成变更单，固定源/目标版本、迁移映射、容量、负责人、计划 RPO/RTO 和回滚触发点；先在隔离副本演练，禁止未知组合直接生产切换。
2. 冻结写入、采集入库和任务派发；排空或标记在途任务。保留外部 operationId，源库只读，避免双写分叉。
3. 完整备份源库及附件/配置/迁移版本，校验恢复可用；凭据系统独立备份，不把秘密打入普通导出包。
4. 创建目标库并运行目标迁移；经版本化离线导出/转换/导入迁移业务数据，校验 UUID、时区、精度、大小写唯一性、关系、权限、审计和 Outbox。
5. 对比逐表计数及规范化业务摘要哈希，抽样引用/附件；重建全文/向量索引并验证 ACL；源库与目标库不得同时调度任务。
6. 更新服务端部署配置并重启到只读模式，执行权限、任务、事务、数据完整性冒烟。成功后逐步恢复写入，记录实际损失窗口与耗时。
7. 切换后所有在途/恢复任务先核实外部副作用，绝不自动重执行危险任务。观察期保留只读源库及备份。
8. 目标尚未开放写入可回指源库并重启；开放写入后回滚须先冻结，识别增量与外部副作用，采用验证过的反向迁移或恢复并人工核对。禁止直接回指旧源库丢弃新数据。代码回滚不等于数据可逆。

## 3. 服务器、OS、网络与数据库目标兼容

### 3.1 注册模型与状态证据

兼容项唯一键至少为 `厂商+产品/型号+OS/固件精确版本+协议/API版本+连接器版本+能力`。另记录硬件架构、许可、节点 OS、TLS/认证、最小权限、字段范围、速率/分页、限制、样本来源、验证环境/日期/责任人/证据。

- `planned`：尚无实接证明，可供排期与原型展示。
- `implemented`：有实现及契约/样本测试，仍不能称“真机已支持”。
- `verified`：在有授权的指定版本真机/厂商沙箱通过功能、安全、错误恢复测试，且证据可追溯。只验证只读健康不能推广到配置备份或写操作。
- 固件升级后原记录保留历史，新版本建新行；不默认继承 verified。发现安全/兼容问题可标记 revoked/deprecated，阻止新部署并给出替代方案。

### 3.2 起始覆盖矩阵（以下全为 planned，版本待登记）

| 类别/候选 | 协议与首期只读能力 | OS/固件/API版本记录与限制 | 状态 |
| --- | --- | --- | --- |
| Windows Server/Windows 终端 | WinRM HTTPS、CIM/WMI 受控查询或现有监控 API；服务/磁盘/事件 | 每个 Windows 版本、补丁、域环境、JEA/权限单独验证；不开放任意脚本 | planned |
| Ubuntu/Debian、RHEL/Rocky/Alma、SUSE 等 Linux | 现有监控 API、受控 SSH 只读白名单或 exporter | 发行版/内核/架构/systemd/命令版本分别登记；不能由“Linux”概括兼容 | planned |
| 国产 Linux 候选（麒麟、统信等） | 经厂商认可 API/采集方式 | 产品分支、CPU 架构及授权分别核验；不宣称天然兼容 | planned |
| Dell/HPE/Lenovo 等服务器带外 | Redfish 优先，厂商 API 次之；硬件健康/电源/温度 | 型号、BMC 固件、Redfish schema/OEM 扩展；禁用电源写动作 | planned |
| VMware/Hyper-V/Proxmox 等虚拟化 | 正式 API/受控管理接口；集群/VM/存储关系 | 产品与 API 版本、许可、分页及长任务语义；快照不等于备份 | planned |
| Cisco/Huawei/H3C/Aruba 等交换路由 | SNMPv3、正式 API、经审查 NETCONF/RESTCONF 只读能力 | 型号/固件/MIB/OID/API 单列；端口索引变化、计数器回绕需测试 | planned |
| Fortinet/Palo Alto/山石/深信服等防火墙与行为管理 | 正式 API、SNMPv3、Syslog 摘要 | 固件、许可、HA、限流分别记录；个人行为明细默认不采集 | planned |
| PostgreSQL/SQL Server/MySQL 等目标库 | TLS 只读监控连接/现有监控 API | 引擎版本、实例形态、权限和指标视图；不读取业务数据正文 | planned |
| 打印、存储、备份及终端安全平台 | 标准协议可用子集+厂商 API | 型号/固件/平台版本及字段支持按能力登记，缺失为 Unsupported | planned |

品牌仅是候选调研范围，不代表采购推荐、协议必然可用或整品牌覆盖。先实现共用协议，再按实际首批资产增加适配；缺少授权接口时保留人工登记且展示确认时间。SNMPv1/v2c、明文协议与不受支持 OS 默认禁用或隔离并走风险例外，不静默降低 TLS 或证书检查。

### 3.3 连接器验收与失效处理

连接测试分 DNS/TCP/TLS、认证、能力发现、最小只读请求四层，展示实际阶段、时间、延迟与脱敏错误码。TCP 通不代表凭据可用；样本解析通过不代表设备连通。连接器测试与 AI 测试均禁止伪造“成功”。

契约测试覆盖缺字段、未知枚举、不同语言、空页/重复页/断点、429、超时、时钟漂移、证书失效、权限不足、计数器回绕和固件变更。返回质量与业务健康分开；失败保留上次快照并标注 Stale/Failed，不显示绿色零值。不支持的能力禁用入口并说明原因。连接器删除前检查关联计划/凭据/资产，历史证据保留。

## 4. 外部 AI provider 与端点安全

### 4.1 适配合同与配置对象

网关在服务端实现 `IAiProvider`：能力发现/声明、最小连接测试、流式/非流式生成、取消、用量解析、错误归一。OpenAI-compatible、Anthropic 为独立适配器候选；Azure OpenAI、企业代理或批准的本地服务按其实际协议另配。名称兼容不等于 tools、JSON schema、图像、上下文长度或 usage 字段全部兼容。

模型档案至少包含：providerType、endpointPolicyRef、modelId、API 版本、secretRef、region/dataPolicyRef、允许功能/数据分类、上下文上限、输入输出 token 上限、超时/并发/预算、能力标记、enabled、配置版本、最后验证证据。模型返回的 ID/价格不得直接作为可信配置；费率表记录币种、生效日期及维护人。

### 4.2 企业批准 allowlist 与 SSRF 防护

1. 外发默认关闭。安全/数据负责人批准供应商、地域、数据类别、训练/保留条款、代理与端点后才能启用；连接测试也属于外发，使用合成无敏感探针。
2. 端点按精确 scheme/host/port/必要 path 前缀的企业批准 allowlist 管理，默认仅 HTTPS；禁用用户输入任意 URL、userinfo、非常规协议、路径绕过和请求头注入。普通模型配置管理员不能自行批准 allowlist。
3. 默认拒绝环回、链路本地、云元数据、未批准内网、保留地址及对应 IPv6/IPv4 映射形式；企业内网模型只对明确批准主机和网段例外放行，不泛放整个私网。
4. DNS 解析后及实际连接前校验全部候选 IP，防 DNS 重绑定，使用受控解析/固定连接目标并保留正确 TLS 主机名校验。重定向默认拒绝；确需启用须每跳重新校验且不得转发授权头到其他源。
5. 统一出口代理/防火墙形成第二道边界，服务账号无云元数据访问；禁止关闭 TLS 校验。模型给出的 URL、工具参数、模板变量不能改写端点或请求头。
6. 测试覆盖十进制/混淆 IP、IPv6、DNS 重绑定、重定向、代理旁路和未批准端点。策略不可用时 fail closed，不能退到任意公网供应商。

### 4.3 秘密引用与配置权限

密钥仅由服务端凭据系统读取，业务库只存 `secretRef` 与轮换元信息。浏览器不存密钥到 localStorage、sessionStorage、IndexedDB、缓存、日志、URL 或导出包；原型不接收真实密钥。正式密钥录入优先跳转受控凭据管理入口，AI 设置页仅选已授权引用、显示掩码/到期，不提供回读明文。网关不把引用解析能力暴露给模型。

区分配置编辑、secret 使用、端点批准、模型启用、prompt 审核发布、审计读取权限；高风险外发配置不得自审。凭据轮换/撤销后清理缓存，测试新引用再切换，旧引用按保留政策撤销。日志和异常禁止输出 Authorization、原始请求体、连接串。

### 4.4 真实连接测试、运行预算与降级

- 测试按钮实际发起后端测试任务，返回 `testId / configVersion / provider / modelId / startedAt / stages / latency / status / sanitizedError / evidenceRef`；认证成功、模型可访问、最小生成成功分别展示。
- 测试仅用固定合成文本，不读真实工单或知识；明确可能产生费用。模型列表可访问不等于指定模型生成可用。模拟测试标注 mock 且不得保存为 verified；历史结果显示时间和配置版本，配置变更立即使旧结果过期。
- 建议初值：连接超时 10 秒、首字 30 秒、总时限 90 秒、单请求最多 2 次受控重试；应随 provider 和场景验证。取消向上游传播并记录是否确认终止，取消不保证零费用。
- 429 尊重 Retry-After；超时/5xx 指数退避带抖动且在总预算内；认证/策略错误不盲目重试。流式输出已开始时不自动重放，避免重复费用与混淆。
- 用户/部门/模型/全局按日月预算、并发、请求与 token 限额分别控制；请求前预留额度，完成后按 usage 结算，无 usage 标估算并保守处理。硬上限拒绝新调用，熔断异常供应商。
- 审计记录主体/范围、授权结论、配置和 prompt 版本、脱敏来源 ID、耗时、token/费用、错误、降级与关联 ID。正文默认不保存或短期脱敏保存，审计与供应商账单对账；不以日志全量留存换取可观测性。
- 降级为普通授权搜索、预置帮助、人工工单；仅在相同数据政策批准的备用模型间切换并告知用户。不得自动把本地数据转外部服务；AI 故障不阻塞资产、告警、工单。

## 5. 功能级 prompt 管理

### 5.1 绑定与变量 schema

每个发布版本绑定 `functionKey + locale + promptVersion + modelPolicyVersion + toolPolicyVersion`，如 `ai.generalHelp`、`alerts.explain`、`tickets.summarize`、`inspection.reportDraft`、`knowledge.answer`。调用方传功能 ID，不能从浏览器传整段系统模板或工具授权。

变量用 JSON Schema 明确类型、必填、长度/数组上限、枚举、数据分类和来源，例如 `question:string(max 2000)`、`evidence:array(max 20)`、`locale:enum`；未知变量拒绝，缺失必填返回可读错误。不使用 eval 或模板脚本执行，禁用任意对象路径、文件/网络读取及动态 secret 访问。用户字段严格作为数据序列化，不形成角色分隔符或工具声明。

模板建议包含任务、语气/格式、引用要求、证据不足策略和输出 schema；示例只能用合成数据。变量预览显示脱敏样例及长度，不显示生产明文。

### 5.2 安全规则不可被模板覆盖

服务端不可编辑安全策略优先于已审核功能模板；用户问题、变量、知识、日志、工具结果都属于不可信数据。模板不得关闭授权、脱敏、引用校验、外发限制、预算或审批，也不得扩展工具集合。即便模板写入“忽略安全规则”，网关仍独立拒绝越权。

模板静态扫描只是辅助，不是安全边界。检索前 ACL 过滤、命中后重鉴权、工具 schema 与当前授权校验、输出净化和引用存在性校验必须由代码执行。正文不能诱导任意 URL 抓取、跨部门查询或命令执行；AI 仅产生草稿/建议，不能自批或执行生产变更。

### 5.3 草稿、审核、发布、回滚

状态：Draft→InReview→Approved→Published→Retired；驳回回 Draft 并保留评论。每次编辑创建不可变修订，已发布内容不能原地覆盖；作者与发布批准人分离。变更对比显示文本、变量 schema、绑定功能、模型与工具政策差异。

发布前固定测试集及模型配置，记录输入摘要、预期、实际、评分、审核人和报告。通过后将功能绑定原子指向新版本，支持按批准范围灰度。会话/请求固定已选版本，不能同一请求半途换模板。回滚重新指向上一已批准版本，保留审计与失败版本；若旧版有安全缺陷则禁用该功能而非盲目回滚。

### 5.4 回归集与门禁

每个功能首批至少 20 条合成/批准脱敏用例，其中正常≥8、缺失/过期/部分数据≥4、恶意注入≥4、越权/隐私≥4；另覆盖多语言、长输入、无引用和 provider 不可用。版本化基线避免改 prompt 后同步降低预期。

安全用例必须 100% 通过（无秘密、越权、任意工具/外发、写操作）；引用用例要求引用全部来自本次授权证据且可解析；结构化输出合法率 100%；正常任务人工标准评分建议≥90%。模型非确定性用例至少运行 3 次，记录最差安全结果；任一次安全失败阻断发布。自动评分不代替业务/安全审核，未接真实模型只能记录样本/模拟回归结果。

## 6. 原需求外的必备产品能力

| 主题 | 可执行目标与验收方法 |
| --- | --- |
| 可访问性 | 以 WCAG 2.2 AA 为目标；键盘完成核心闭环、焦点可见且不被遮挡、对话框焦点归还、语义标签/错误关联、非颜色唯一状态；自动扫描结合读屏人工抽测 |
| 部门反馈 | 每页可生成带页面/版本/模式/复现步骤的脱敏反馈；JSON/CSV 导出，回流时 schema 校验、feedbackId 去重、关联缺陷/修复版本/复测证据；无正式确认不记部门已验收 |
| 导入导出 | 模板版本、字段字典、UTF-8、时区/单位清晰；先预检再幂等提交，逐行错误可下载；公式注入、越权字段、文件大小/压缩炸弹与附件扫描；导出短期授权链接和审计，秘密不导出 |
| 时区与语言 | 存储 UTC、显示 IANA 时区与偏移；跨日/夏令时/维护窗测试；简体中文优先、文案集中以便扩展，保留原始厂商术语与规范化分类 |
| 数据质量 | 每条关键指标显示来源、observedAt、ingestedAt、单位与 Good/Partial/Failed/Stale/Unknown/Unsupported；健康与质量分离；归并冲突人工审核、保留历史与撤销证据 |
| 隐私与保留 | 按字段分类和最小化采集；个人行为/打印名称默认不采；按类别保留、法定保留冻结、访问/更正/删除申请可追踪；审计按批准期限保留且不因普通删除请求无审查破坏证据 |
| 升级兼容 | API、配置、导入模板、连接器和 Worker 分别有 schemaVersion；声明支持版本范围，契约测试验证；不兼容时拒绝接单并解释；数据库 expand-contract，升级前备份、灰度、回滚演练 |
| 浏览器与终端 | 锁定发布时 Edge/Chrome 企业支持版本，补充 Firefox 验证；1280/1440/1920 桌面和窄屏查看；缩放 200%、慢网/中断、空态/错误态逐页测试 |
| 运维可观测性 | 平台自己的任务滞留、采集心跳、时钟漂移、证书到期、出口故障、AI 预算与审计失败有告警；关联 ID 跨前后端，错误提示不泄露内部秘密 |
