## 2. 建设目标、范围与非目标

### 2.1 目标

建立统一入口，回答资产归属、异常位置、处理方法、操作记录和证据来源五类问题。优先降低日常切换管理后台、手工巡检和重复排障成本。所有信息显示来源、观测时间与质量；所有变更绑定操作者、授权、审批、具体目标和执行结果。

### 2.2 范围分层

1. **基础平台**：身份、角色与范围权限、审计、组织和站点、配置、文件、连接器、持久任务。
2. **MVP**：资产、统一首页/搜索、核心只读监控与告警、AD 查询、受限网络诊断、备份登记/同步、轻工单、巡检、知识库和 AI 只读帮助。
3. **深化接入**：共享权限解释、网络配置备份、行为管理、杀毒、虚拟化、打印、授权与维保台账；优先只读。
4. **受控变更**：AD 解锁/重置、按组授权、打印作业处置、设备运维操作、入转离清单与审批任务。
5. **后续优化**：跨系统流程、权限到期回收、员工自助、容量分析，AI 仅提出审批计划。

### 2.3 非目标

不自研防火墙、杀毒引擎、虚拟化平台、完整备份引擎或通用全厂商监控底座；不建设完整 ERP/采购财务/复杂 ITSM；不提供无限制 Shell、未经审批网络策略下发、AI 自主处置、默认全量日志外发、自动删除生产数据。已有监控与管理产品优先集成，不重复采集全部高频指标。

## 3. 用户、授权与职责分离

### 3.1 权限模型

采用 `RBAC + 资源范围 + 属性约束`：有效权限为用户角色权限与组织/站点/资产组范围的交集，再检查数据分类、目标状态、时间窗口及操作风险。拒绝优先，默认拒绝。统一策略服务处理列表、详情、聚合、搜索、导出、附件、任务结果、AI 检索和工具调用；不能只在控制器入口验证角色。

权限命名示例：`assets.read`、`assets.update`、`alerts.acknowledge`、`directory.read`、`directory.unlock.request`、`changes.approve`、`tasks.execute`、`knowledge.publish`、`audit.read`、`connectors.manage`。范围取自服务端用户会话和数据库授权，不接受客户端声明的可访问资产集合。

| 角色 | 默认可做 | 默认禁止 |
| --- | --- | --- |
| 只读观察者 | 范围内看板、资产、摘要 | 变更、原始敏感日志、凭据、无范围导出 |
| 值班运维 | 确认告警、处理工单、受限诊断、发起操作 | 自批高风险操作、任意执行、管理身份权限 |
| 专项运维（AD/网络/终端等） | 对应领域和范围内申请/执行已批准模板 | 自动获得其他领域管理能力 |
| 审批人/部门负责人 | 审批本人负责的资源/业务申请 | 以审批身份直接执行、审批自己的申请 |
| IT 负责人 | 跨部门授权范围的风险、报表、流程监督 | 默认读取全部个人行为明细或凭据 |
| 安全审计员 | 授权审计、导出证据、复核 | 修改审计、执行生产操作 |
| 平台管理员 | 连接器、节点、模板发布、角色配置 | 仅因平台管理员身份获得所有业务数据及域管理权 |
| 员工（后期） | 本人工单、员工可见知识、本人申请 | 他人工单、内部日志、管理接口 |
| 服务身份 | 指定连接器/节点/任务能力 | 人类交互登录、跨节点领取任务 |

同一人员可兼任角色但高风险申请者和审批者必须不同；若企业仅一人运维，应指定管理层审批或正式应急授权，不能静默取消分权。应急通道限时、MFA、指定理由和范围、全审计、事后复核。授权撤销须使会话、缓存、AI 会话及待执行任务失效或重新校验。

### 3.2 身份接入

优先对接企业现有支持 OIDC 的身份提供方；若仅有 AD，评审 Windows 集成认证或受控身份桥接，再确定实现，不能把“已有 AD”视为“已有 OIDC”。禁止自行实现通用口令验证系统。浏览器建议使用同源 BFF/服务端会话、HttpOnly/Secure/SameSite Cookie 和防 CSRF 令牌；不把访问令牌放入 localStorage。高风险操作要求 MFA/近期重认证。节点使用独立 mTLS 证书，不复用浏览器会话。

## 4. 总体架构与模块边界

```text
用户浏览器
  │ HTTPS，同源登录与 CSRF 防护
反向代理 / Web 静态资源
  │
ASP.NET Core 模块化单体 API
  ├─ 身份授权 / 资产 / 领域查询 / 告警 / 工单 / 知识库
  ├─ 任务审批 / 连接器编排 / 审计 / AI 网关
  └─ BackgroundService：调度、租约、发件箱、告警计算、保留清理
  │             │                  │
PostgreSQL16   受控附件存储       凭据管理系统
  │
节点控制面 HTTPS + mTLS（节点主动拉取、续租、回传）
  ├─ Windows 只读采集节点 → 厂商 API / SNMPv3 / AD / Windows
  └─ Windows 受控执行节点 → JEA/受限 PowerShell / 厂商变更 API
AI 网关 → 授权检索/只读工具 → 已批准的本地或外部模型
```

节点可共用部署包但必须以配置、证书、身份和能力授权隔离只读/写入。生产高权限执行建议独立服务与主机。节点不直连业务数据库；管理目标不直接暴露给浏览器；AI 模型与管理网之间没有直连执行通道。

### 4.2 所有权与依赖

| 模块 | 拥有数据/职责 | 对外合同 |
| --- | --- | --- |
| Identity | 用户映射、角色、权限、资源范围、会话 | 当前主体与资源授权 |
| Assets | 资产、外部标识、关系、组织站点、软件授权 | 资产查询、归并审核、资产变化事件 |
| Integrations | 连接器、能力、采集计划、游标、节点 | 规范化观测批次、节点领取协议 |
| Observability | 观测、事件、规则、告警、维护窗、通知 | 告警查询与生命周期事件 |
| Directory / Files | AD 对象、组关系、共享及 ACL 快照 | 只读查询、受控操作计划 |
| Network / Endpoint / Virtualization / Printing / Backup | 各领域快照、关系、恢复验证 | 领域查询、诊断、操作模板元信息 |
| ServiceDesk | 工单、变更、入转离清单、审批业务上下文 | 工单状态、审批需求 |
| Automation | 模板版本、任务、尝试、租约、审批绑定、调度 | 提交、执行授权、状态查询 |
| Knowledge / Inspection | 知识版本 ACL、巡检项、报告 | 已发布检索内容、巡检结果 |
| AI | 会话、检索编排、工具注册、模型策略、调用记录 | 有来源的只读回答/待人工提交的计划 |
| Audit / Platform | 追加审计、附件元数据、保留策略、配置 | 写审计、授权证据查询 |

模块不直接修改其他模块表，跨模块写入走应用服务/命令；查询通过授权的只读合同或专用投影，禁止绕开权限直接任意联表。初期同库不同 PostgreSQL schema，每模块 DbContext 与独立迁移历史；跨模块使用逻辑 UUID 引用并由应用校验，核心强一致流程尽量放在同一模块事务内。共享只限基础类型，不创建包罗所有业务的公共服务。

同模块用本地事务；跨模块可靠事件使用事务发件箱和消费去重（Inbox）。例如任务状态与其 Outbox 一次提交，工单投影异步更新，不假定分布式强事务。读模型应呈现同步时间与必要的“处理中”。

## 5. 运维功能设计与业务规则

### 5.1 首页、搜索与资产

- 首页按优先级展示紧急告警、待办/审批、昨夜备份、核心服务健康、采集失联、容量和到期提醒；所有卡片受同一范围权限过滤。
- 全局搜索支持资产编号、主机名、IP、用户、工单、知识；先分类型查询，再聚合授权结果，不通过搜索建议泄漏不可见对象名称。
- 资产涵盖网络、服务器、终端、打印、虚拟化、软件授权和证书维保。人工字段（用途、负责人、位置）与采集字段（OS、状态）分开保存，字段所有权明确。
- 稳定标识优先序列号、硬件 UUID、AD objectGUID、厂商对象 ID；外部 ID 唯一键包含连接器。IP/MAC 只作线索，不自动认定为同一资产。
- 归并冲突进入人工确认，保留来源和历史。退役为生命周期状态，不物理删掉告警、审计关联。导入先预检、预览、逐行错误报告，再幂等提交；导出处理公式注入并审计。

### 5.2 AD 与员工入转离

只读采集用户、计算机、OU、组、直接/嵌套成员关系、启用/锁定、到期策略、最后登录证据和高权组变化。`lastLogonTimestamp` 等可能延迟，不将其直接称为精确最后登录；密码到期需考虑细粒度策略。锁定来源仅在已启用相关审计并能读取有关域控事件时给出证据，不保证总能定位。

后续解锁/重置使用专用模板和 OU 范围委派。敏感输入采用独立受保护一次性通道或批准的凭据系统，业务任务参数、日志、审计、文档、AI 上下文均不持久化其明文；不能使用普通 JSON 表单日志承载秘密。

入职按版本化岗位模板建号、入组、领用设备；调岗生成权限差异并先回收不再需要的权限；离职建立禁用账号、回收组/VPN/第三方访问、会话撤销、设备回收、数据交接、保留与最终清理的独立清单。每一步独立任务和人工确认，支持部分完成与补偿，不能用“AD 已禁用”代替全域离职完成。删除账号或数据不纳入初期模板。

### 5.3 文件共享与授权

登记服务器、UNC 路径、用途、业务负责人、容量配额、备份策略，采集共享 ACL、NTFS ACL、继承来源、拒绝项及 SID。优先安全组授权。权限解释显示“用户→组嵌套→ACE→继承→共享/NTFS 合并”的证据路径；考虑令牌刷新、特殊权限、DFS、条件 ACE、访问上下文，无法准确模拟时标记“需在目标环境验证”，不得声称 ACL 展示等于有效权限。

权限流程：申请目录与权限等级/期限→业务负责人审批→技术审核→预检快照→按组变更→回读验证→到期复核或回收。变更并发时比对 ACL 版本摘要，禁止覆写期间他人修改。访问审计只覆盖已启用并授权的事件；不索引文件正文作为默认采集范围。误删恢复走恢复申请并由备份平台执行。

### 5.4 网络、防火墙、行为管理与 IPAM

- 防火墙：在线、CPU/内存、接口流量、连接数、VPN、HA；交换机：端口、VLAN、速率、错误包、丢包与上联；行为管理：健康、策略版本变化、安全事件摘要，个人访问明细单独授权及保留。
- IPAM：网段、VLAN、网关、用途、静态/保留/租约地址、状态、证据时间；DHCP 租约/ARP/MAC 表形成置信线索，探测无响应不能标记空闲，冲突必须有多源证据。
- 网络诊断：Ping、有限跳数路由跟踪、DNS、TCP 检测。限定注册目标、批准网段/端口、节点、时间和频率；拒绝任意 URL、云元数据/环回/链路本地目标以及未授权管理地址。企业授权私网可用，不能简单封禁全部私网。
- 解析后与连接前均校验目标 IP，固定解析结果，防 DNS 重绑定；IPv6 同样验证。禁止命令拼接或用诊断探测任意互联网。
- 配置备份通过只读接口取得，文件内容视为高敏感：去除可识别秘密后用于普通对比，原始版本如确需保留仅进专用加密库，禁止进入日志/AI/知识库。网络策略下发不在 MVP。

### 5.5 杀毒与终端健康

通过现有平台 API 获取在线、防护、病毒库、威胁状态、隔离状态与厂商处置 ID。覆盖率分母必须说明是已登记活跃终端还是 AD 清单；清单缺失不能直接断言未安装。与资产、使用人关联，威胁原始分类保留并映射统一等级。后续扫描、隔离、解除隔离各自模板化，高影响服务器隔离必须专门审批和维护窗/应急依据；回读厂商状态才认定完成。

### 5.6 服务器与虚拟化

采集 Windows 服务、磁盘、关键事件和宿主机/集群/VM/数据存储关系。展示容量趋势、资源压力、快照年龄与大小、长期关机和备份关联。快照不是备份，低利用率不触发自动回收。新建、扩容、下线先走工单和容量校验；后期开关机/重启/资源调整需业务依赖、备份、维护窗、执行前状态和恢复步骤。长时厂商任务保存 externalJobId 并持续查询，API 返回接受不等于成功。

### 5.7 打印

采集设备位置、型号、耗材（仅设备支持时）、驱动、共享队列、Spooler、队列积压和作业状态。默认不采集文档内容，文档名可含个人信息应脱敏。取消单个作业优先；清理队列或重启服务明确影响范围、审批并逐项确认，禁止默认一键清空全组织队列。作业 ID 结合服务器、队列、提交时间形成定位键，执行前核实未被复用。

### 5.8 备份与恢复

对接现有备份产品，记录受保护资产、策略、保留、最近成功、任务结果、存储容量、失败次数、RPO/RTO、恢复负责人和演练记录。无法接入时允许人工登记，但明显标注人工来源与确认时间，不能伪装实时监控。备份成功、最近可用恢复点、最近恢复验证分别展示。

恢复申请明确目标数据/时间点、恢复位置、业务授权、覆盖风险、恶意软件检查及验证者；优先隔离位置恢复，生产覆盖需要高风险审批。AD 系统状态/森林恢复按微软支持流程和组织演练手册执行，平台只管理记录与受控步骤，不自造恢复算法。

### 5.9 工单、变更、巡检、知识与报告

- 工单：类型、优先级、申请者、指派、资产、处理记录、附件、SLA 计时、关联告警/任务。状态建议 New→Assigned→InProgress→Waiting→Resolved→Closed，可经理由重开；等待是否暂停 SLA 由策略决定。
- 变更：范围、风险、计划窗口、前置条件、执行步骤、验证、回退、审批；变更记录不同于机器任务，一个变更可含多个任务。
- 巡检：版本化检查项和阈值、定时执行、逐项正常/异常/未知/不适用；仅当必填项采集完整才能形成“通过”，异常转工单保留去重关联。
- 知识：Draft→Review→Published→Archived，负责人、产品版本、有效期、ACL、附件；AI 生成草稿需人工审阅后发布，不能直接进入可信知识检索。
- 日/周报：按有权限数据生成，指标口径与时间窗固定；趋势需样本量、缺失率和算法说明，AI 摘要与确定性统计分离。

## 6. 数据模型、字段与关系

### 6.1 通用规范

主键 UUID；时间使用 UTC `timestamptz`，前端按用户时区展示；IP 用 `inet`、网段用 `cidr`。金额/容量/比例用明确单位及精度，禁止混用 GB/GiB。可变聚合带 `version bigint` 乐观并发，更新时 `WHERE version = expected` 并自增。业务表通常有 `created_at/created_by/updated_at/updated_by`；快照有 `observed_at/ingested_at/source_id/quality`。

质量值：`Good/Partial/Failed/Stale/Unknown/Unsupported`，与业务健康 `Healthy/Warning/Critical/Unknown` 独立。JSONB 仅放版本化厂商扩展、已验证参数和证据摘要，核心可查字段不得全部塞入 JSON。秘密只存引用，禁止在 `parameters/result/payload` 等任意字段夹带凭据。

### 6.3 关键关系与容量

- 资产一对多外部标识/观测/告警，多对多工单/备份策略；资产关系形成有类型的依赖图。
- 连接器一对多采集计划，计划触发任务，任务一对多尝试/步骤/审计；审批只授权确定的一次任务计划。
- 工单可关联多个告警/任务；机器成功不自动关闭业务工单，必须满足业务验证。
- 知识文档一对多版本/片段；片段继承当前文档访问策略，不复制成无人维护的公开 ACL。
- 索引重点：资产编号/名称与外部键、`observation(asset_id,metric_key,observed_at desc)`、告警活跃指纹、任务 `(state,scheduled_at)`、租约到期、审计时间/主体/关联 ID。大观测/事件/审计表按月分区，保留删除按分区执行。
- 初期 PostgreSQL 存业务与有限指标，附件进受控文件/对象存储。粗估每日样本数=`资产数×每资产指标数×86400/采集秒数`；上线前按真实规模压测、估算索引/WAL/备份空间。高频监控优先留在现有监控系统，仅汇总必要数据。
- 知识先用 PostgreSQL 全文/关键词检索验证效果；中文分词及可选 pgvector 在评测后引入，不把向量库作为 MVP 必需依赖。

## 7. API 规范与示例

### 7.1 通用约定

- 前缀 `/api/v1`，JSON camelCase，UUID 字符串，时间 RFC3339 UTC，枚举字符串且有 OpenAPI 定义。由 OpenAPI 生成 TypeScript 客户端，契约变化由 CI 检查。
- 列表统一 `page/pageSize/sort/filter`，`pageSize` 默认 25、上限 100；大事件流使用不透明 cursor。排序字段白名单且追加唯一 ID 稳定排序；过滤采用受限 DTO，不透传 SQL/OData 任意表达式。
- 正常返回资源或 `{items,page,pageSize,total,asOf}`；`total` 仅为授权范围内数量。采集详情带 `observedAt/source/quality`。
- 201 创建资源，202 接受异步任务并提供 `Location`，204 无正文；400 参数错误，401 未登录，403 已知资源但无操作权，404 不存在或需隐藏存在性，409 幂等/状态冲突，412 版本不匹配，422 业务前置条件失败，429 限流，503 依赖不可用。
- 错误使用 Problem Details：`type/title/status/detail/instance/code/traceId/errors`；不返回堆栈、SQL、凭据或目标设备内部敏感信息。
- 修改用 ETag/If-Match；任务、审批决定、导入提交、手工变更创建要求 `Idempotency-Key`。幂等记录与资源创建同事务，默认保留 7 天（上线评审可调整）；长生命周期操作另有永久业务唯一键。
- 所有查询/导出仍做资源级过滤；批量目标逐个授权，不因其中一个有权限放行全部。

## 8. 持久任务、审批、幂等与执行安全

### 8.1 状态机

```text
Draft → PendingApproval → Approved → Queued → Leased → Running → Verifying → Succeeded
  └─（只读且策略免审批）────────────→ Queued
PendingApproval → Rejected / Expired / Cancelled
Approved → Expired / Cancelled / Queued
Queued → Cancelled / Expired
Leased → Running / Queued（仅能证明尚未开始）/ Unknown
Running → Verifying / RetryWaiting / Failed / CancelRequested / Unknown
Verifying → Succeeded / Failed / Unknown
RetryWaiting → Queued / Cancelled / Expired
CancelRequested → Cancelled（确认未产生或已停止副作用）/ Verifying / Unknown
Unknown → Reconciling → Succeeded / Failed / Queued（经核实可安全重试）
```

`TimedOut` 作为尝试失败原因，而非“确认目标未变更”；执行超时或断线无法判定时任务进入 Unknown。失败不等于已回退；部分成功以步骤结果记录，整体可为 Failed 并显示 `partial=true`，不能把批量部分成功标成全部成功。补偿为独立受控任务，不能篡改原结果。

### 8.2 调度与领取

1. API 在单事务内写任务、幂等记录、审计和 Outbox，再返回 202。
2. BackgroundService 扫描到期计划，用 `(schedule_id,occurrence_at)` 唯一键创建任务。时间使用数据库 UTC；带时区计划明确夏令时重复/缺失处理。默认漏跑只补最近一次，危险变更不因宕机补跑。
3. 调度器以 `SELECT ... FOR UPDATE SKIP LOCKED` 在短事务内领取可用记录，分配租约/尝试和 fencing token；不能持事务锁执行远程操作。
4. 节点按能力、区域、模板版本领取，起步可采用 60 秒租约、20 秒续租（需压测调整），后台设置并发上限、目标锁、连接器限流和熔断。
5. 节点开始前重新向控制面校验授权、审批摘要、维护窗、模板哈希、目标现状和租约有效性。授权撤销、目标变化或模板禁用立即拒绝。
6. 节点上传序号化事件/结果；重复上传由 `(attempt_id,sequence)` 去重，过期 fencing token 不允许覆盖新结果。节点失联后写操作不自动派给另一节点重做。

初期 BackgroundService 与 API 同进程即可，生产配置常驻且禁止空闲回收；多实例通过数据库租约协调。若将来独立宿主运行同一调度模块，也仍只共享这一套任务账本。

### 8.3 幂等与不确定性

平台只承诺至少一次交付与可审计的幂等控制，不承诺跨设备 exactly-once。模板必须声明：

- `ReadOnlyRetryable`：只读，可限次指数退避加抖动，通常 3 次以内。
- `DesiredState`：设置期望状态，先查当前状态、记录外部标识，再应用/回读；达到目标则跳过。
- `ExternalIdempotency`：厂商支持幂等键，复用 operationId 并查询外部任务。
- `NonRetryable`：不可逆或无法识别重复，超时进入 Unknown 并人工核实，禁止自动重试。

并发键如 `assetId + operationFamily` 防止同资产冲突操作；分布式租约/fencing 只能约束平台结果，无法让不支持 fencing 的外部设备停止旧命令。因此目标端单写锁、JEA 限制、执行中本地互斥及失联冻结缺一不可；不确定时牺牲自动恢复速度，先人工核实。

### 8.4 审批绑定

审批摘要由规范化的目标 ID/快照、模板版本与哈希、全部非敏感参数、秘密引用版本（如适用）、风险、执行人范围、维护窗、前置条件及回退计划计算。字段变化、有效期届满、角色撤销或目标状态不满足均需重审，不得审批后偷偷替换目标。

低风险只读诊断可策略免审批但保留用户发起与审计；AD 解锁等依据风险单人业务确认；权限、批量变更或服务中断需要业务/技术审批；不可逆删除初期不开放。审批不是永久授权，领取和执行前都重新鉴权；审批人不可为申请者，高风险不允许自动批准。

### 8.5 PowerShell 白名单

模板由代码审查、测试、签名/哈希验证后发布到节点，发布版本不可变。API 只传模板 code/version 和强类型参数，不接受脚本文本、命令路径、任意表达式或任意模块名称。通过 SDK/参数绑定调用固定命令，禁止字符串拼接与 `Invoke-Expression`。限定可用 cmdlet、模块版本、路径根、目标资源、超时、输出大小和编码；使用 JEA/委派权限，不以域管理员常驻运行。

为每次运行建立隔离进程、受控环境和资源限额；超时先请求取消再终止进程树，但目标端仍可能已生效，必须回读验证。PowerShell ExecutionPolicy 不是安全边界，需结合账户权限、应用控制、网络隔离及签名校验。只记录脱敏结构化输出，不无差别开启会泄漏敏感输入的转录日志。

### 8.6 Redis/Hangfire 引入规则

仅当实测数据库轮询延迟、吞吐或调度管理成本不满足目标时出 ADR 评审。Redis 可仅作缓存/限流且不是任务真相；Hangfire 若获批准则用单一适配器替换现有调度机制，业务状态、审批和审计仍在业务表。迁移顺序：暂停新领取→清点运行中任务→冻结/核实未知任务→导入尚未执行任务与幂等映射→停用旧调度→启用新调度→验证唯一执行→保留回退开关。禁止两套调度器同时驱动同一任务。

## 9. 连接器、采集与数据质量

### 9.1 接口与能力协商

连接器合同包含 `DiscoverCapabilities`、`TestConnection`、`CollectSnapshot`、`CollectDelta`、`Normalize`、`Health`；变更能力单独接口注册，并交给任务引擎管理。能力描述包括产品/版本、支持对象与字段、读取/操作权限、速率、分页、增量、时间精度、外部任务查询能力。不能以同厂商品牌推断全部版本 API 一致。

优先顺序：已有监控/管理平台 API→厂商正式 API→SNMPv3/受控 Windows 管理→审查过的只读脚本；受控 SSH 仅限有明确只读命令集的设备。Syslog 经独立接收端/网关归一化，校验来源并记录不可靠传输/丢包风险。SNMPv2 或未加密协议仅作为例外需网络隔离和风险批准。

### 9.2 采集流程

计划选择节点与范围→连接与能力检查→分页/增量读取→标准化/校验→批次幂等入库→更新游标→告警计算/投影。部分分页失败记录 Partial，不把未返回对象立即删除。全量多次缺失且经过确认窗口后才标记失踪/退役候选；增量删除以来源墓碑为准。初始同步、断点恢复和全量校正均有运行记录。

建议起始频率（非已承诺 SLA）：核心健康 1–5 分钟、容量 5–15 分钟、AD 15–60 分钟、资产每日全量+可用增量、备份完成后同步并每日补扫；按接口额度、规模和业务要求调整。默认过期阈值为 `max(采集周期×3,连接器最小阈值)`，必须可配置。

超时、重试、批量尺寸、最大并发、输出上限、代理和 TLS 验证统一策略；限流尊重厂商 Retry-After。采集账号只读并按 OU/资源委派。DNS、NTP、证书过期与连接器心跳本身纳入监控。使用缓存不可隐藏 observedAt，失败时保留上次数据但标记 Failed/Stale。

## 10. 告警治理与通知闭环

规则按观测窗口、连续次数、触发/恢复阈值（滞回）计算，单次缺失不能视为恢复。指纹通常为 `ruleVersion + assetId + normalizedDimension`，同活跃指纹更新 lastSeen/count，不反复创建告警；规则版本迁移须明确关闭旧告警或映射。

状态为 New→Acknowledged→InProgress→Recovered→Closed；可自动恢复，但关闭需满足业务策略。被人工关闭的持续异常不得永远沉默，应按规则重开或新建下一事件并记录关联。维护窗和依赖抑制是附加状态，不覆盖真实健康状态。

- 分级：P1 关键业务中断、P2 显著风险、P3 一般异常、Info 事件；严重度与业务关键度联合决定通知策略。
- 聚合：上联/宿主故障可抑制已知下游重复通知，但显示受影响资产；依赖未知时不猜测根因或完全抑制。
- 维护：必须有范围、时限、原因、审批；窗内继续采集，退出后重新计算，不把维护中资产当健康。
- 抖动：设置最短持续时间、恢复保持、通知冷却；异常长期存在可按策略升级负责人。
- 通知：只选企业实际采用的邮件/企业微信/钉钉渠道，消息不含秘密和超出接收者权限的明细。提供回到平台的受授权链接，不发永不过期直达附件。
- 可靠性：Outbox 推送、唯一通知键、限次重试/死信、渠道健康告警；告警状态不依赖通知成功。支持值班表、夜间静默、P1 例外和人工测试通知。
- 指标：发现到通知延迟、确认/恢复时长、误报率、重复通知率、采集未知占比、未关联负责人比例。告警风暴情况下限制通知而非丢弃事件证据。

## 11. AI 数据流、权限与防注入

### 11.1 只读数据流

```text
用户问题 + 当前会话
 → 网关校验身份/范围/速率/数据外发策略
 → 意图识别（不把模型输出当授权）
 → 检索前按文档 ACL 和资源范围过滤候选
 → 对命中内容及附件再次鉴权、脱敏、限量
 → 模型选择已注册只读工具
 → 工具网关校验 schema、当前主体、目标/时间窗/预算
 → 应用层授权查询，结果带来源、时间和质量
 → 内容作为不可信证据交给模型总结
 → 输出事实/推测/证据缺口/建议与可点击引用
 → 脱敏审计、质量反馈、按期限清理
```

检索前过滤是必要条件，检索后再次鉴权防 ACL 撤销竞态；索引更新延迟期间以源文档当前 ACL 为准。禁止先把未授权片段交给模型再做答案过滤。向量/全文、缓存、会话历史、自动补全和引用下载均纳入同一授权；缓存键含主体/范围摘要、authzVersion、数据版本，撤权触发失效。用户追问不能复用已失去访问权的历史敏感证据。

### 11.2 工具边界

首批注册 `assets.search`、`alerts.list`、`observations.query`、`directory.userSummary`、`backups.summary`、`knowledge.search`、`tickets.read`。工具只接受结构化参数，固定最大时间窗、结果数和调用预算；不开放任意 SQL、HTTP fetch、文件读取、PowerShell、节点领取或写接口。只读也需要最小化，不能允许枚举全公司个人行为信息。

网络诊断虽非配置变更但可对外产生流量，MVP 由用户在普通工具页面显式发起，不让模型自行扫描。AI 可解释现有诊断结果。后期模型只能生成结构化 proposal，用户在独立预览页显式提交后，由平台走原有任务/审批链；AI 无法批准、修改审批或绕过任务引擎。

### 11.3 提示注入防护

日志、知识正文、工单、网页、厂商响应以及模型返回均为不可信数据，其中“忽略规则”“调用工具”“发送凭据”等文本不具有指令效力。系统规则与证据分区、工具白名单和服务器校验共同约束；仅靠提示词或过滤关键词不足以安全。

检索片段附来源/版本/分类标签，限制长度；禁止工具结果诱导任意 URL 抓取、外发或跨用户检索。输出 Markdown 禁止原始 HTML、脚本和不受控图片远程加载，链接经协议白名单处理，外链访问由用户确认。答案引用须来自本次实际检索证据，不接受模型自造资源 ID；找不到依据时明确“无法确认”。

### 11.4 模型与数据政策

默认外发关闭，待安全负责人批准模型供应商、数据类别、地域、保留/训练条款及费用后启用。仅发送问题所需最小脱敏片段；秘密检测发现疑似凭据时阻断，不仅替换后继续。个人信息和路径按场景掩码，映射表留在服务端；模型不接触秘密引用解密能力。本地模型同样受权限、隔离与审计要求。

设置单用户/会话 token 预算、超时、并发、熔断、取消与费用统计。模型不可用时回退普通查询/检索和人工流程，不阻塞资产、告警和工单。对话默认短期保留，可按合规政策关闭正文保存；审计记录工具名、授权结论、来源 ID、模型版本与费用，不记录秘密或无限量原始日志。

图表与表格显示时区、采集时间、来源、缺失率。任务输出默认摘要，查看详细日志需要独立权限。AI 使用固定结构卡片、引用与时间，生成草稿标识未执行。基本满足键盘操作、颜色非唯一状态表达、可读对比度与响应式布局。

## 13. 安全、凭据与审计

### 13.1 安全基线

HTTPS 全链路；生产代理配置可信来源与转发头，严格 AllowedHosts、CORS 同源/白名单、CSP、安全响应头、请求大小限制、速率限制、会话超时、CSRF 防护。OpenAPI 生产默认关闭或仅内网认证可见。错误与健康接口不泄露配置。

所有接口参数化查询，文件上传限类型/尺寸、恶意文件扫描、隔离存储；下载鉴权并禁止路径穿越。富文本净化，CSV 导出防公式注入；厂商返回同样视为外部输入。定期漏洞扫描、依赖锁定、SBOM、签名制品与模板审核。执行节点到管理目标采用出站白名单，限制横向移动。

### 13.2 凭据全生命周期

- 开发使用开发者本机批准的安全配置机制，真实值不提交版本库；本次设计不需要也不读取任何 user secrets。
- 生产凭据进企业现有 Vault/受控密钥系统；Windows 适用场景优先 gMSA/证书。若暂无统一系统，可评审由专用服务身份保护的 Windows 加密凭据存储作为过渡，但必须覆盖轮换、恢复和审计。
- 数据库仅记录 secret_ref，节点按任务、用途和目标获得最短期访问权限；认证材料不得回传浏览器、写文档、写普通日志或进入 AI。
- DB 运行账号只获业务所需权限，迁移账号独立、按发布临时授予 DDL；只读连接器无生产变更权，执行身份不默认域管理员。
- 轮换覆盖 DB、节点证书、厂商 API、通知与模型凭据；验证新版本后撤销旧版本，泄漏时立即吊销、停任务、核实范围与复盘。
- 应用日志采用允许字段列表和默认脱敏，禁止记录请求 Authorization/Cookie、连接串、敏感表单、原始 PowerShell 参数或完整厂商配置。

### 13.3 审计证据

审计记录主体（人/节点）、来源地址、时间、动作、资源、授权决策、请求/任务/审批/外部操作 ID、参数摘要、前后状态摘要、结果及失败原因。读取高敏感资料、导出、角色变更、模板发布、凭据引用使用同样审计。

变更事务和审计/Outbox 一起提交；关键变更若无法写审计则拒绝启动，不能静默成功。节点断联期间仅将必要脱敏事件写受保护本地 spool，不启动新高风险任务；恢复后按序补传。数据库追加权限、分离审计角色、哈希链与外部只追加/不可变归档结合；单纯同库哈希不能抵抗拥有整库控制权的攻击者。

建议初始保留（待合规批准）：原始指标 30 天、小时汇总 12 个月、普通事件 90 天、任务摘要/工单 2 年、安全审计至少 1 年、AI 正文 30 天或不保存；行为/文件访问日志单独按合法目的确定最小期限。法律保留优先于自动删除；到期清理含副本/索引/附件并记录清理任务。

## 14. 开发、测试与生产部署

### 14.1 开发环境

开发机安装受支持的 .NET 10 SDK、Node.js LTS 与包管理器，版本在仓库工具清单锁定；PostgreSQL 16 用隔离容器或专用开发实例。前端 Vite 代理到 API，使用假连接器/模拟设备数据；真实 AD 测试仅使用独立测试域和最小权限。现有 API 端口只是模板开发值。

建议后续实施顺序：建立模块骨架→依赖兼容测试→授权基础→DbContext/迁移→持久任务账本→假连接器→业务纵切→Worker 契约→真实只读试点。开发配置仅记录键名和秘密引用要求，禁止复制生产连接串。

后续标准验证命令（本次仅执行过 `build --no-restore`，未执行此处完整 restore/test 流程）：

```powershell
dotnet restore src/backend/OpsPlatform.slnx
dotnet build src/backend/OpsPlatform.slnx
dotnet test src/backend/OpsPlatform.slnx
# 有正式迁移后，由发布流程生成审查过的迁移脚本/迁移包，不在生产启动时自动迁移。
```

当前解决方案没有已确认的测试项目，上述 test 命令本身不能证明存在或通过业务测试。前端、Worker 与测试工程创建后再固化相应 CI 命令。

### 14.2 生产拓扑

初期：内网 HTTPS 反向代理/Web 静态站点 + 常驻 ASP.NET Core API/BackgroundService + PostgreSQL 16 + 受控附件存储 + 至少一个 Windows 采集节点；高权执行节点在受控操作上线前独立部署。API 可运行在 Windows Service 或受支持 Linux 环境，按团队能力决定，不因 Worker 使用 Windows 强制整个系统同机。

网络区域：用户区只访问 HTTPS 入口；应用区只连 DB/附件/身份/秘密服务和批准模型出口；节点主动连接控制面，节点到目标端口按连接器白名单开通（如 HTTPS、LDAPS、WinRM HTTPS、SNMPv3 等，经清单批准）。不让浏览器访问数据库或目标 WinRM，不广泛开放管理端口；WMI/RPC 若不可避免单独评审动态端口风险。

生产配置：数据库 TLS、受控 DNS/NTP、证书自动到期提醒、服务自动恢复、磁盘与日志配额、附加本机故障日志；API `/health/live` 检查进程，`/health/ready` 检查关键依赖，不把模型不可用作为核心服务不就绪条件。

负载提高后可加 API 实例，Cookie/Data Protection 密钥需安全共享，任务通过 DB 租约协调；无共享内存会话假设。PostgreSQL HA/副本按业务 SLA 决定，备份不等于高可用，高可用也不能替代备份。初期不要求 Kubernetes。

### 14.3 发布与回滚

流水线：格式/静态检查→单元与契约→PostgreSQL 集成→前端构建/E2E→安全扫描→制品签名→测试环境演练→备份/迁移审批→生产发布→冒烟/指标观察。数据库采用 expand-contract 迁移，先兼容新增再切代码，破坏性变更另窗口；迁移由独立身份单实例执行。

部署前暂停高风险新领取，让运行任务排空；未完成任务标明核实策略。API/Worker/模板协商最低兼容版本，不兼容节点不能接新任务。代码回滚不能盲目回滚数据结构；有数据损失风险时按恢复方案操作。保留上一稳定制品与迁移审查记录。

## 15. 平台自身备份、恢复与业务连续性

建议试点目标（须业务批准）：平台 RPO ≤15 分钟、RTO ≤4 小时；不是对外部业务系统的承诺。PostgreSQL 每日基础备份+连续 WAL 归档支持 PITR；小规模逻辑备份用于选择性恢复而不是取代 WAL 方案。备份包含业务库、迁移版本、附件、配置清单、模板发布制品、必要证书/密钥恢复材料及其权限信息；密钥与数据分开保管，凭据系统使用自身安全备份流程。

采用异机/异介质/异地及至少一份不可变或离线副本，备份加密、最小访问、完整性校验，按批准保留策略清理。每季度至少一次隔离恢复演练并记录实际 RPO/RTO、抽样数据和附件校验。

恢复步骤：

1. 宣告故障并冻结任务派发、吊销可疑节点/凭据，保存现场审计。
2. 准备隔离网络，恢复数据库到指定恢复点，校验迁移版本和基本完整性。
3. 恢复匹配附件/模板/配置与必要密钥，处理晚于 DB 恢复点的孤立附件，不自动删除证据。
4. 启动 API 只读模式，验证登录、权限、核心查询、审计链与文件下载。
5. **所有恢复出的 Leased/Running/Verifying/Unknown 任务统一进入核实队列**；不得因租约过期自动执行，目标设备副作用不会随 DB 回滚。
6. 查询外部系统核对 operationId/实际状态，人工决定完成、失败、补偿或安全重试；计划任务默认不补跑危险操作。
7. 重建检索索引/缓存并验证 ACL；试运行采集，数据质量稳定后逐步开放审批与执行。
8. 业务负责人验收，记录恢复点、数据缺口、实际恢复耗时与改进项。

AI 故障只影响辅助入口；通知渠道故障可改人工值守；节点失联显示未知而非正常；数据库不可用时拒绝新变更和任务领取，避免无账执行。

## 16. 测试策略与可验证验收

### 16.1 测试层次

- 单元：权限交集、状态机、审批摘要、幂等、告警窗口、字段归属、脱敏、时间/时区。
- 集成：真实 PostgreSQL 16、Npgsql/EF 迁移、唯一约束、事务 Outbox、SKIP LOCKED、多实例租约与并发、保留分区。
- 契约：OpenAPI/生成客户端、节点协议、各厂商脱敏响应样本、分页/限流/字段缺失/版本差异。
- E2E：不同角色登录、搜索→详情→告警→工单；预览→审批→执行→验证→审计；AI 引用与不可用回退。
- 安全：IDOR/BOLA、CSRF/XSS、文件/路径穿越、SSRF/DNS 重绑定、命令注入、越权导出、凭据泄漏、节点冒充/重放、模板篡改。
- 故障注入：DB 事务前后崩溃、节点执行后回传前断线、旧租约延迟结果、重复发件箱、批准后撤权、部分批量失败、通知超时、模型不可用。
- 恢复：PITR、附件一致性、密钥恢复、未知任务核实、索引 ACL 重建。

### 16.2 验收矩阵

| 场景 | 必须达到的可检查结果 |
| --- | --- |
| 模板基线 | 实施前确认模板现状；不把依赖安装、文档或页面占位视为功能交付 |
| 资产同步 | 同一外部稳定 ID 重复同步不产生重复资产；人工用途不被采集覆盖；冲突可审核 |
| 权限 | 至少两部门/两站点交叉测试，列表、详情、统计、导出、附件、AI 均无越权数据 |
| 采集质量 | 断网/超时/部分结果分别显示 Failed/Partial/Stale，不出现“全部正常” |
| 告警闭环 | 可触发、去重、通知、确认、关联工单、恢复与关闭，所有转换有记录 |
| 任务持久性 | 进程重启后队列不丢失；同幂等键相同请求得到同任务，不同请求返回冲突 |
| 审批安全 | 审批后改目标/参数/模板/窗口、审批过期或撤权均拒绝执行 |
| 执行不确定性 | 模拟目标已生效但回传丢失，任务进入 Unknown，不自动重做写操作 |
| 节点安全 | 未授权节点、篡改模板、过期租约不能执行/覆盖结果；敏感参数不进入日志 |
| AD/共享 | 嵌套组/拒绝/继承存在时展示证据及限制，不能把推算直接称为实测权限 |
| 备份 | 最近成功备份和恢复验证独立；至少一次隔离恢复有证据与实际耗时 |
| AI 越权/注入 | 恶意文档、日志中的指令不能触发写工具/外发；撤权后不再检索或重放受限内容 |
| AI 可信 | 引用可打开且来自本次证据，缺失数据明确说明；模型中断不阻塞核心流程 |
| 秘密与审计 | 代码/文档/日志/任务/AI 扫描无秘密；关键变更无法写审计时不执行 |

### 16.3 初始性能目标与测量条件

在规模确认前仅设可调整的试点目标：常规列表/详情 API P95 ≤1 秒、全局搜索 P95 ≤2 秒；已入库事件至平台告警生成 ≤30 秒；通知入队后 P95 ≤60 秒（不含外部渠道故障）；人工任务入队至可用节点领取 P95 ≤15 秒。AI 单独统计首字/完整回答与引用正确率，不用 AI 延迟影响核心 SLA。

压测报告必须注明资产数、指标数、采集周期、数据保留、并发用户、节点数、硬件与网络条件；在预计峰值两倍负载下验证无越权、任务不丢、无重复危险执行。性能不达标先检查索引、批量、采集频率和慢查询，再评估缓存/调度组件。
