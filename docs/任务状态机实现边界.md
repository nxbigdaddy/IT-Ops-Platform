# 任务状态机实现边界

第26轮实现纯函数TaskLifecycle；不含API、队列、Worker、数据库或设备操作。

允许路径：AwaitingApproval → Approved → Queued → Running → Succeeded/Failed。审批前、已批准和排队阶段可以取消；运行中不允许简单标记Cancelled，因为中止等待不代表撤销设备副作用。第27轮增加Running + Timeout → OutcomeUnknown，未知结果不允许自动重试/取消/直接成功或失败，只有ReconcileSucceeded/ReconcileFailed可进入相应终态；调用方必须先核实目标侧证据并授权核实操作，事件本身不是证据。运行中取消请求、部分完成和补偿流程仍待建模。

每次转换要求expectedVersion等于快照版本，成功后版本加一，终态不可重启。失败不改变原快照，重复Start和跳过审批拒绝。失败重试须创建新任务并重新授权/核验审批，不能把终态改回Running。

**重要**：纯函数版本比较不是并发锁，两份相同旧快照各自都可能通过。未来存储必须原子compare-and-swap；审批消费、任务入队及outbox应在同一事务提交。TaskEvent.Approve只是状态事件，调用方必须先校验可信审批，不允许客户端自报事件绕过权限。当前返回Executed始终false。

第29轮新增DemoTaskStore，锁内执行版本比较及状态写回，最多100条，满额拒绝而不淘汰正在处理的任务。同进程同实例旧版本竞争只有一个成功；重启/新实例不共享，不能提供多实例互斥。它没有授权、审批消费、出站调用或持久化，第32轮起仅注册为Demo API服务；不得直接暴露Apply作为生产操作入口。

第31轮增加成功迁移的内存顺序记录，含事件与版本，查询返回副本。记录与状态在同一锁内更新；不含操作者/时间/可信签名/持久化，不等于安全审计。当前无环状态图使每任务最多5条迁移记录（100任务最多500条）；未来重试/循环设计必须重新检查容量。

第32轮Demo接口：POST /api/v1/demo-tasks创建，GET /{id}读取，GET /{id}/history查询，POST /{id}/transitions提交 `{event:"Approve",expectedVersion:1}`。仅Development Demo+本机开放，事件只是模拟状态，绝不授权或执行。创建/迁移结果的data内包含task及executed=false，信封persistence=memory；读取状态目前为枚举数字，接入界面时需显式映射，未知值拒绝。

第69–79轮新增IDemoTaskStore及锁内Read，GET /{id}/snapshot一次返回task与history的同一读取时刻快照。联调页“读取模拟迁移记录”使用此接口，验证任务ID、版本非回退及完整历史后一起更新，不保证响应后任务不会前进；下一次写入仍必须带expectedVersion。快照读取不新增执行、审批或审计能力。

第119–120轮起，迁移请求可带上可选 `idempotencyKey`。带键时先在同一进程内存操作台账中认领：同键同载荷已提交返回200并把 `replayedVersion` 设为原结果版本且**不再推进状态**；同键不同载荷返回409 `idempotency_payload_conflict`；仍在处理中返回409 `operation_in_progress`；结果未定返回409 `operation_outcome_unknown`；台账满返回409 `operation_capacity_reached`；被校验/版本拒绝后释放认领，允许用同键重试。台账为进程内存且单实例，无持久唯一约束、无过期墓碑、无权威查询接口，因此**不是生产幂等保证**；不带键的请求行为与之前完全一致。

前端联调面板对所有迁移请求附加确定性幂等键（任务ID + 事件 + 预期版本），并提供“重发上次迁移（同幂等键）”按钮。重放响应由新增的 `replayedVersion` 字段识别：界面显示“服务器已确认该操作此前提交过（结果版本 vN）”，状态与迁移历史均不改变；重放版本高于当前快照或不是正整数时整份拒绝。该字段缺失按普通成功处理，因此旧后端仍兼容。

第134轮起，面板必须在操作前显式“核对任务状态词汇表”：`GET /api/v1/demo-task-vocabulary` 由 `TaskLifecycle` 实际规则推导出状态、事件与全部允许迁移。界面把该词汇表与自身的状态标签表、事件目标表逐项比较，不一致即**保持未核对状态**：不显示状态名、不显示迁移按钮、禁用迁移/历史/导出/重发并给出明确说明，从而避免后端调整枚举后界面静默误标状态。核对成功后恢复显示与操作。

导出的“模拟任务证据”为结构化记录：每条迁移含版本、事件、来源状态与目标状态（另附中文显示行），并记录本次已核对词汇表的规模（状态数/事件数/迁移数）与状态值。因导出按钮只有在核对通过后可用，文件中的标签始终来自已核对的映射；但它仍不是生产审计日志，也不代表真实审批或执行。

前端已有工单模拟状态不是本状态机的实现，不应混淆工单流程与自动化执行任务。
