# 已知问题与下一迭代清单

> 生成与运行方式见 [原型演示说明](原型演示说明.md)；逐条用例结果请填入包内 `case-records-template.csv`。

## 1. 已知缺口（本批明确未实现）

| 编号 | 缺口 | 影响 | 现状 |
| --- | --- | --- | --- |
| K-01 | 无鉴权与页面级无权限态 | 无法演示“无权限”夹具，不能作为访问控制证据 | 未实现；仅“角色展示模拟”。需 L2 只读试点（含授权与审计）后再演示 |
| K-02 | 无生产持久化 | 默认启动仍为进程内存；可选的**关系型模式**（EF Core + SQLite 本地文件）已为反馈与幂等台账提供**真实事务与唯一索引**，但仍无迁移历史、保留策略、行级安全与审计，（现覆盖**全部四个端口**：反馈、台账、任务、提示词） | 部分实现：数据库唯一性与事务已可运行并实测跨重启；**生产数据库、迁移、任务/提示词的关系型实现与多实例协调仍未实现**，契约继续报告非持久化 |
| K-03 | 无真实设备/数据库/模型连接 | 所有连接器、数据库与 AI 面板均为规则与演示数据；AI 侧已有**本机回环往返**（服务端请求自身的合成桩），但它不是模型，也不联网 | 未实现；请求端点受 Demo 门控（生产 503、外域 403），回环传输强制 loopback 且不读凭据 |
| K-04 | 提示词无真实审批与发布生效 | 发布修订不可变、发布**必须携带审批记录**（合成引用+审批人，一个引用只授权一次），但没有鉴权、没有审批系统集成、没有两人规则/时效/撤销，也没有生效开关或回滚到线上的机制 | 部分实现：发布前置校验与追溯已落地；真实审批系统、职责分离与生效链路**未实现** |
| K-05 | 任务与研究型 AI 无执行链路 | 任务模拟不执行命令；AI 仅有离线契约与请求形状预览 | 未实现；数字签名、可信存储与事务消费均缺失 |
| K-06 | 部分验收清单用例未纳入本批 | 24 个 UI 用例显式排除（见《原型范围与case映射》） | 排除项不得视为通过 |
| K-07 | 工单/资产等业务域为固定样本 | 行为不代表真实数据分布与性能 | 未接入真实来源；页面已标注限制 |

## 2. 本批已修复（供追溯）

- 连接器预检“取消等待”按钮在请求进行中被禁用，导致无法取消（第184轮修复，并补取消场景测试）。
- 提示词功能覆盖面板按钮禁用条件误用 `busy!==null`（布尔恒不等于 null），导致按钮不可点（第183轮修复）。
- 打包脚本按本地代码页解码中文文件名失败（第173轮修复：脚本改为 UTF-8 带 BOM）。

## 3. 下一迭代候选（按优先级）

1. **P0 持久化落地**：按《持久化迁移契约草案》实现真实数据库适配与版本化迁移，补齐事务/CAS 与唯一约束的集成测试（不得用内存 provider 代替证据）；替换 `IOperationLedger`/`IDemoFeedbackStore`/`IDemoTaskStore`/`IPromptCatalog` 的进程内实现。
2. **P0 鉴权与授权**：实现真实身份、角色与站点范围校验，使“无权限”夹具可演示；接通 `OperationAuthorization`/`ApprovalBinding`/`ExecutionPreflight` 到真实请求管线（当前仅只读规则视图）。
3. **P1 只读连接器试点**：按 L2 门禁接入一个只读设备/数据库来源，验证采集、凭据托管、最小化数据与审计。
4. **P1 部门反馈闭环**：把本机反馈导出与评审证据包接入受控台账，形成“意见→处理→复测”的可追溯记录。
5. **P2 范围扩展**：按《原型范围与case映射》逐步纳入当前排除的 24 个 UI 用例，并同步更新脚本与文档。

## 4. 结论填写规则

本清单不构成验收结论。部门参与者与意见、复测版本、P0/P1 未清数量需在评审时如实填写；无实际签认不得写“用户已验收”。
